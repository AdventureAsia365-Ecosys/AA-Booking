# AA-910 — Staff admin at 1440 px + audit rows

Issue: Linear AA-910 (S244 master plan finding N4). The exact leftovers come from the AA-683 and AA-822 closing
comments (S239): at 1440 px the `/suppliers`, supplier Contracts tab, `/hotels`, hotel rates and `/services` tables
scroll sideways (the Contracts "⋯" column is off-screen), the row menu closes when the click scrolls it into view,
the tab strip shows a 1 px scrollbar, and the FX tab Source column wraps to 3 lines.

## Decisions

- **Target: every listed table fits its frame at 1440 px; below that it scrolls inside its own box, never the page.**
  Measured frames at 1440 px (expanded sidebar): list pages 1084 px, supplier detail tabs 1092 px, hotel drawer 837 px.
  At 1280 px the list tables scroll inside their frame (924 / 932 px) and the page itself never scrolls.
- **Root cause of the overflow:** `truncate` inside a kit DataTable cell never cut anything. An auto-layout table cell
  grows to its content, so a long supplier name, e-mail, contract title or "hotel · room type" made the column
  500-780 px wide. Fix: every free-text cell has a desktop max width (`md:max-w-[…]`) with the full text in a
  `title` tooltip. The `md:` prefix keeps phone cards (DataTable card mode below 768 px) showing the full text.
- **Columns merged where the width budget needed it (no new design, kit tokens only):**
  - `/suppliers`: Location moved under the supplier name (`SUP-000001 · Hoi An, Vietnam`); "Contracts in force" →
    "Contracts".
  - Contracts tab: validity stacked (`1 Jan 2026` / `to 31 Mar 2027`); "Entered / published by" → "Entered by" with
    "Published by …" on a second line.
  - `/hotels`: hotel style under the name; "Updated" under the status pill; "Room types" → "Rooms", "Rates in force" →
    "Rates" (tooltip "Rates in force"); the place header reads "Place (CIS)" instead of a "From CIS" chip in every row.
  - `/services`: pricing unit under the type ("Activity" / "per person"); "Updated" under the status pill; "Max
    group" → "Max pax"; "Rates in force" → "Rates"; no per-row "From CIS" chip (header "Place (CIS)").
  - Rates table (supplier Rates tab, hotel drawer, service page): season + validity share one column, meal plan + pax
    band share one column; the target shows the room type / service on top and `HTL-… · hotel` under it.
- **Hotel drawer** goes from 680 to 880 px (full width on phones as before) and its rates table uses a new `compact`
  mode (no code line, narrower text cells, the validity dates may wrap): 8 columns could not fit 637 px.
- **The "⋯" column stays visible.** A wrapper class `bk-dt-sticky-end` (globals.css, ≥ 768 px) pins the last column
  to the right edge of the table's own scroll box. Used on every table whose last column is a row menu.
- **The kit DataTable (`ui/DataTable.tsx`, byte-comparable with CIS) is not touched.** Everything is page-level
  (cell content, wrapper class, CSS on the wrapper), so the CIS copy rule holds.
- **Tab strip 1 px scrollbar:** `SavedTabs` hung its tabs 1 px below the strip (`-mb-px`) inside `overflow-x: auto`,
  so the strip overflowed 1 px vertically and drew a scrollbar. The baseline is now an inset shadow inside the strip
  (`bk-tabstrip-line`), and every tab strip (`SavedTabs`, `DetailHeader`, case page) uses `bk-tabstrip`
  (`overflow-y: hidden`, no visible scrollbar, still swipeable on phones).
- **Row menu closing on open:** a click on a partly hidden "⋯" scrolls it into view (focus), and that scroll arrived
  just after opening and closed the menu. `RowMenu` now scrolls the trigger into view itself, places the panel at
  the final rect, and for 400 ms after opening a scroll moves the panel instead of closing it. With the sticky menu
  column the horizontal case no longer happens on these pages; the guard covers any other scroll container.
- **Audit rows (scope item 2) — what was really missing.** Room type create / update (`hotel_room_type.*`) and rate
  create / update / delete (`supplier_rate.*`) already wrote `booking.audit_logs` rows since bk-010 (#14, 15/10). The
  S244 finding came from the pages: no supplier, hotel or service page listed a rate's row, so the maker-checker trail
  looked empty. Room types have no delete endpoint (they are deactivated by an update), so no `hotel_room_type.deleted`.
  Change: the supplier page's recent activity now includes the rate rows of its hotels' room types and its services,
  the hotel page the rates of its room types, the service page its own rates — deleted rates included, because the
  target is read from the row's own `before` / `after` snapshot first, then from the live rate (an update row keeps only
  the changed fields). SQL constants `RATE_ROOM_TYPE` / `RATE_SERVICE` in `app/suppliers/service.py`.
- **Superseded V1 gets its own row.** "Superseded" is a derived badge (`sql.VERSION_BADGE`): sending V2 writes nothing
  to V1, so the trail showed "V2 sent" and never that V1 stopped being the offer. `send_version` and `approve_version`
  read the badges of the live versions before and after the write and record one `trip_case_version.superseded` row
  per version that turned superseded (entity = that version, `before = {badge}`, `after = {badge: superseded,
  superseded_by: N, by: sent|approved}`, summary `V1 superseded: V2 was sent`). A version already superseded gets no
  second row; the version being sent / approved is never one.
- **Audit log page labels**: `AUDIT_ENTITY_LABEL` lists every `entity_type` the backend writes today (supply, pricing,
  FX, trip plan, departure, B2B hold / partner, retention), and supplier / service rows link to their page (both pages
  resolve a UUID).
- **FX tab:** Source is one line on desktop (cut at 180 px, full text in the tooltip); the rate and "As of" never
  wrap. `Code` and `FromCisTag` never wrap or shrink (a `SUP-000001` used to break at its hyphen next to a long
  location).

## Changed

- Backend (audit): `app/suppliers/service.py` (supplier activity + rate SQL constants), `app/supply/records.py`
  (hotel / service activity), `app/trip_cases/versions.py` (superseded rows). Tests: unit
  `tests/unit/test_w1_services.py` (send / approve / first send), integration `test_bk005_w1.py` (real
  `VERSION_BADGE` SQL) and `test_bk010_supply_api.py` (rate rows on the three pages, a deleted rate included).
- Frontend (audit): activity lists on the supplier, hotel and service pages show the rate label; `ui/booking/audit.ts`.
- Frontend only for the layout: `app/globals.css`, `ui/booking/{RowMenu,PersonCell,Code,FromCis}.tsx`,
  `app/(staff)/_parts/{SavedTabs,DetailHeader,supply}.tsx`, the suppliers list / detail, hotels list / drawer,
  services list, pricing rules view, case page tab strip.

## Tradeoffs

- Superseded rows cost two extra badge reads per send / approve (one small query each, same transaction); the
  alternative, a stored `superseded_at` column, needs a migration and a backfill for a badge that is derived on read.
- The rate subqueries in the activity SQL scan the page's room types / services; the lists are LIMIT 20 and the
  supply tables are small (hundreds of rows), so no new index.

- Merging columns loses header-click sorting on Location (suppliers), Style (hotels), Updated (hotels, services),
  Season and Pax (rates). The server-side Sort select ("Recently updated", etc.) still covers the lists; the rates
  tables are short (one contract / hotel).
- Hiding the tab strip scrollbar means a mouse user on a very narrow desktop window scrolls the tabs with the wheel
  or trackpad; at ≥ 768 px every tab strip here fits.
- Sticky last column paints the card colour; a selected-row tint (no table here uses selection) would not show on it.

## S249 — repeatable layout check (`npm run test:layout`)

AA-910 could not close on a signed-in check: the E2E staff account deliberately has no Booking role (CIS
`e2e-cognito` asserts the refusal). The S248 harness lived only in a session folder. S249 turns it into a committed
Playwright project and fixes what it found.

### Decisions

- **Playwright project `layout-mock` in `frontend/`** (`playwright.config.ts`, `e2e/layout/`), `@playwright/test`
  1.59.1 as a dev dependency (same version as AA-CIS-App). It serves the **production build** (`next start`), not
  `next dev`, so CSS and chunks are what Vercel serves.
- **Mock at the network layer, no app change, no test flag.** Browser calls to the BFF (`/api/booking/*`) are
  answered by `page.route` from `e2e/layout/fixtures.ts`; the one server-side call (`GET /booking/staff/me` from the
  `(staff)` layout) goes to `e2e/layout/stub-api.mjs` through the check's own `BOOKING_API_URL`. The session is an
  unsigned JWT in `bk_access` shaped like a Cognito access token. This is safe because `proxy.ts` and the layout only
  **decode** the token to pick refresh / login routing; trust is in the Booking API, which verifies the Cognito
  signature. Nothing in the app reads a test flag, so there is nothing to switch on in production.
- **Fixtures are typed against `lib/api`** and are the worst realistic case: full 25-row pages, long company / hotel /
  service / tour names, 60-80 character e-mails, every optional field filled, all trip case statuses (incl.
  "Supplier confirming"), seven FX rows with six decimals and a long source. A type change that a fixture no longer
  satisfies fails `npm run typecheck`. Any BFF call without a fixture fails the test (`unmocked`), so a page that
  starts calling a new endpoint is noticed.
- **Pages**: every route under `app/(staff)` that renders a kit DataTable, with the tab or drawer that holds it (20
  entries incl. the audit log feed, which is not a DataTable but had a page-level overflow). Pages without a table
  (billing, trip checks, notifications, settings, countries, destinations, calculator, forms) are out of scope.
- **Assertions at 1440 x 900, light and dark**: document and `<main>` scrollWidth <= clientWidth (and <= innerWidth);
  every table fits its own scroll box (`scrollWidth <= clientWidth`), last header inside the box, the box is not
  `<main>`; **min-content of each table leaves >= 20 px** (lesson S239: Firefox on Windows has a ~17 px scrollbar
  vs Chromium's 6 px; measured by squeezing the table to width 0 and restoring it); tab strips have no vertical
  overflow and no scrollbar; FX tab currency / rate / buffer / as-of / source cells are one line (line boxes counted
  from text-node client rects); Poppins really loaded (widths depend on the brand font, so Google Fonts are let
  through; every other external request is stubbed); `data-theme` matches the scheme; console clean.
- **1280 x 800 squeeze (light)**: the page still never scrolls sideways; tables may scroll inside their own box (the
  AA-910 design below 1440); where the last column is the row menu (`bk-dt-sticky-end`) it is `position: sticky` and
  in view.
- **Scrollbars on**: `ignoreDefaultArgs: ["--hide-scrollbars"]` (lesson S239).
- **390 x 844 phone (light)**: page-level checks only (the kit DataTable shows cards below 768 px); the Linear
  Done-when asks for 390 too.
- **Not wired into Booking CI.** A full run is ~4.2 min locally (80 tests, one worker) on top of the build and a
  Chromium download, above the 3-minute budget for this lane. The command is documented in `frontend/README.md`;
  adding it later to the `frontend-build` job after `npm run build` is two steps
  (`npx playwright install --with-deps chromium`, `npm run test:layout`).

### Tradeoffs

- `/cases` loses two header-sort columns: Pax (now in "Dates / pax", accessor starts with the start date, so the
  header still sorts by date) and Updated (now under Status, accessor `status · updated_at`, so the header sorts by
  status, then update time). The list's default server sort is still `-updated_at`; the CSV keeps both values.
- Flagged customers (chip wraps under the name) get one more line in their row; unflagged rows are unchanged.
- The compact rates table in the hotel drawer cuts the room type at 130 px ("Family Suite with …", full text in the
  tooltip); the drawer already names the hotel.
- A mocked API proves layout with chosen data, not the Dev data. The fixtures are deliberately longer than typical
  rows, so a pass here is the stricter case; real-data differences (a field shape the fixtures do not model) are
  caught only by the typecheck on the fixture types.
- Google Fonts are fetched live during the run: without network the Poppins assertion fails (on purpose, the
  widths would be wrong with a fallback font).

### Should know

- Run: `npx playwright install chromium` once, `npm run build`, `npm run test:layout`; `LAYOUT_SHOTS_DIR=<dir>` writes
  the screenshots and `measurements.{json,md}` elsewhere (default `e2e/layout/results/`, gitignored). Ports 3199
  (`next start`) and 55481 (stub), override with `LAYOUT_PORT` / `LAYOUT_STUB_PORT`. Outside CI an already running
  server on those ports is reused.
- A new page with a table, or a new API call on a listed page, needs a `PAGES` entry and a fixture.
