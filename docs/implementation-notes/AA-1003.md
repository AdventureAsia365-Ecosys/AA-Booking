# AA-1003 — Booking part: inquiry inbox key contract view (bk-035)

## Decisions

- **`booking.v_ops_inquiry_inbox (source, idempotency_key, status, received_at, processed_at, has_trip_case)`**,
  inbox rows of contract `inquiry.submitted`, last 30 days, as the CIS request in AA-CIS-App
  `docs/implementation-notes/AA-1003.md` ("R2 follow-up requests", item 3). The CIS TP-03 hourly check matches each
  key with `tripplanner.v_ops_inquiry_keys` (tp-022).
- **`has_trip_case`** = a `trip_cases` row with the same `idempotency_key` (the intake writes it; its no-op path looks
  it up the same way; `trip_cases_idempotency_key_uq` makes it an index probe). Soft-deleted cases count: the inquiry
  did become a case. `inbox_event_id` was not used: it has no index and the no-op path does not set it.
- **Contract file, not expand.** The request asked for an expand file. The AA-CIS-Infra expand lint refuses any
  grant to `cis_app` from a booking/ file ("an expand file grants only to the booking owner's runtime / nologin
  roles"); root ADR 0017 keeps cross-owner grants manual. A split (expand view + contract grant) saves no manual step
  and the plain `CREATE VIEW` it needs is not re-runnable (the integration tests replay every file), so the file
  follows bk-017 / bk-025: guard, `CREATE OR REPLACE VIEW`, `REVOKE` of the default DML, grants.

## Changed

- `test_bk017_ops_views.py`: the exact `cis_app` grant set gains `v_ops_inquiry_inbox`.

## Tradeoffs

- `error` (pii:free_text) is left out: CIS gets the status (parked / failed) and its age, the reason stays in the
  Booking inbox page.
