# AA-1096 l23 — Pricing > Policy explains every parameter

Tech lead feedback (S279): "the thresholds on the Settings page are hard to understand; each needs an explanation or
definition so I know when to change it". The CIS Platform › Settings page links its Booking tab to this page, so
Booking's 39 pricing policy parameters (bk-050 and bk-056) get the same guide. CIS ships the registry side (CIS 415).

## Decisions

- **Guides in code, no bk- migration.** Booking's parameter definitions are `app/pricing/policy_params.PARAMS` (code);
  the tables hold only versions. So the guide is code next to them: `app/pricing/policy_guides.py`, one entry per key,
  `{"en": {what, raise, lower, when, example}, "vi": {...}}` (the platform-wide shape, AA-CIS-App CONTEXT.md).
- **Served by `policy_admin.list_params`, not `policy_params.describe`.** `policy_params.py` is in the code-health
  file-size baseline (826 lines, over the 800 limit): it must not grow. The listing adds `guide` next to the
  definition.
- **Page.** Under each label the short "what" (two lines, the full text in the tooltip; the old one-line help when a
  parameter has no guide), an Explain toggle per row with the whole guide in place, the same guide at the top of the
  change drawer, the old help as a collapsed "Engineering note". The two directions are named by type: number "If you
  raise / lower it", yes/no "If you switch it on / off", a day "If you move it later / earlier", a list or map "The
  stricter / looser choice". New UI lives in `_parts/PolicyGuide.tsx` and the pure helpers in `lib/policyGuide.ts`
  (complexity baselines of `PolicyView.tsx` / `textToValue` do not move).
- **Decimal comma.** A decimal parameter takes `2,5` as `2.5` (`decimalText`). Lists and maps keep the comma as their
  separator, so only the decimal type changes.

## Changed

- `GET /booking/pricing/policy` items gain `guide` (additive; no response model, the OpenAPI document is unchanged).
- The help line under each label is replaced by the guide's short "what".

## Tradeoffs

- Guide text in code is reviewed with the definition it explains, at the cost of a PR for a wording fix; a
  free-text help store editable on the page was rejected (the meaning of a bound is not an operator's edit).
- The guides of parameters that are not enforced yet describe the effect once the feature reads them; the page's
  "Not enforced yet" badge and reason stay next to them.

## Should know

- A new parameter needs its guide in the same PR, or `tests/unit/test_aa1096_policy_guides.py` is red.
- The layout-mock fixtures carry an invented guide on every parameter (`e2e/layout/fixtures.ts`).
