# AA-1074 — lane l31 (S277): finance UI fixes from the signed-in UAT

Lane l31 of session S277 (Claude Code). Two findings of the signed-in Booking UAT on Dev (root
`docs/audits/2026-11-11-S277-booking-uat/`, findings 1 and 2). The main AA-1074 notes are `AA-1074.md` (lane l16).

## Decisions

- **Tour title on every finance departure read, not only the list.** The UAT saw the raw catalog key in the Costs &
  profit → Departure costs list; the same key also showed in the departure drawer header (`GET /departures/{id}/costs`)
  and in Profit → Per departure (`GET /finance/profit/departures`). All three now carry `tour_title`.
- **Same lookup as the B2B desk**: `app.b2b.desk.tour_titles` (`catalog.v_tour` by `source_id`, inside a savepoint,
  empty on a catalog error). One read per page through `app.finance.departure_costs.with_tour_titles`; the profit read
  titles only the page it returns (after the offset / limit slice), not every row of the window.
- **UI fallback** `tourLabel(title, key)` = the title, else `Tour <first 8 chars of the key>` (the desk's form), so the
  raw UUID never fills the cell; the full key stays in the cell's `title` tooltip for support.
- **Cost vs billed**: when the panel shows the USD summary (`usd` in the response), the per-currency totals line keeps
  only the non-USD currencies (`nativeTotals`). A USD-only case shows one summary; a case with EUR lines still shows its
  EUR line. Without `usd` (older response) every currency line stays.
- Pure helpers live in `frontend/ui/booking/financeLabels.ts` so `npm run test:unit` (Node's runner) can test them.

## Changed

- Backend: `tour_title` added to three responses (additive; no SQL view or migration change).
- Frontend: Departure costs list + drawer, Profit per departure, Cost vs billed panel; types in `lib/api/finance.ts`;
  layout/visual fixtures carry titles (one row without, to show the fallback).
- The signed-in smoke assertion (Tour column is not a UUID, no repeated USD line) lives in the signed-in smoke branch
  of lane l30 (its `frontend/e2e/signed-in/` is not on main yet); see the lane result.

## Tradeoffs

- Importing `tour_titles` from `app.b2b.desk` into `app.finance` instead of moving it to `app.catalog`: smaller diff
  while another lane edits nearby Booking files; a later refactor can move it.
- The catalog read is outside the views: a SQL join on `catalog.v_tour` would fail the whole read when the catalog
  is unavailable, the helper degrades to `null` titles instead.

## Should know

- `catalog.v_tour` by `source_id` is the plain tour view (not a parse-backed one), allowed by the AA-996 perf guard.
- No new permission, no new field in the B2B API (`booking.b2b.v1`); the finance routes stay staff only.
