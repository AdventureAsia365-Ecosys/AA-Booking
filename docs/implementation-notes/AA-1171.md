# AA-1171 — Alerts catalogue P0 (Booking part)

Lane l12 of S287 (tech lead decisions D1, D3; root `docs/audits/2026-11-21-S287-alerting-inventory/README.md` §8).

## Decisions

- The two job check thresholds (`STUCK_AFTER_S = 900`, `kinds.OVERDUE_FACTOR = 2`) are pricing policy parameters in
  a new section "ops" ("Job checks"), approver group `admin`: `ops_jobs_stuck_after_s` (integer seconds, 120–7200)
  and `ops_jobs_overdue_factor` (decimal, 1.2–10). Seeds by bk-063 = today's values. No constant left.
- No fallback value in code (the Booking policy rule): a tick whose policy has no value in force is skipped with one
  warning; the missing `ops_metrics_sampled` line trips the new Infra alarm `<booking prefix>-worker-silent`.
- `GET /booking/ops/checks` is the check registry for the CIS alerts catalogue ("ops check registry v1": app, version,
  as_of, checks[key, title, component, severity, kind, action, thresholds[setting, value, unit, editable_via, where,
  label], channel, last_alert_at]). The last alert comes from the `bk_ops_alert` ledger rows.
- Auth: the CIS catalogue relays the staff member's own CIS admin token, which the staff verifier refuses (other client).
  A second verifier, WORKFORCE x {cis-admin client} (`COGNITO_CIS_ADMIN_CLIENT_ID`, set by AA-CIS-Infra), is consulted on
  this one route only; groups `cis-admin` or any `booking-*`. No staff row is written.

## Changed

- `kinds.overdue_after_seconds(kind, factor)` and `metrics.backlog_sample(..., overdue_factor)` take the factor;
  `ops_checks.findings(sample, thresholds)` takes the values in force; the finding details carry them.

## Tradeoffs

- A separate verifier instead of adding the CIS client to the staff verifier: the staff routes keep refusing every
  token that is not the booking-staff client.
