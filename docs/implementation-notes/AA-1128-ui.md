# AA-1128 UI slice: Booking names, copy and catalog (S283 UI audit, Booking rows)

The season calendar fix (B1) has its own notes (`AA-1128.md`, the backend PR). This slice is the Booking batch of the
audit (root `docs/audits/2026-11-17-S283-fe-audit/README.md` section 6) that fits one PR.

## Decisions

- **Names, not ids (B3)**
  - Trip cases (list, dashboard, detail): the API adds `party_agency_name` (a scalar subquery on
    `booking.b2b_partners` by `tenant_id`; the staff connection binds no tenant, the same read the departure board and
    agency billing already do). The UI shows the name and a plain sub-line ("B2B agency booking", "Agency not in
    Booking yet"); the tenant UUID is never rendered (`ui/booking/caseFacts.ts` `casePartyLabel` / `casePartySub`).
  - Tour lifecycle notifications: the tour title from `catalog.v_tour` (read in a savepoint: a missing view, grant or
    a cut read never aborts the pull), else the newest trip case itinerary line of the key (a retired tour has left
    the view), the key only as a last resort; `data.tour_title` too. Existing notification rows keep their text (no
    backfill: they are history).
  - Agency payments: `recorded_by_name` / `approved_by_name` / `rejected_by_name` beside the refs (the refs stay, the
    maker-checker compares them). A `cog:` ref with no directory name reads "A staff member", never the subject.
  - Audit log: a label for every entity type the backend writes (price list version, agency, payments, policy, ...);
    the filter options follow the map.
- **Copy (B4)**: the inactive-staff tiles say what the number is (never signed in or deactivated); "Pre-sale" tab
  instead of "Active"; no "Inquiries" tab (the B2C intake is retired; an old link opens All); trip checks "resolved"
  (not-applicable counts, it is not "done"); B2B versions say "approved" / "agency"; settings sign-in text (company
  e-mail code, no password) and a formatted date; "(UI spec Q18)" removed; singular "1 day" everywhere a trip length
  shows (`ui/booking/plural.ts`); dashboard pipeline shows "opened so far this month · in all of last month" instead of
  a month-to-date vs whole-month delta; invoice breadcrumb says "Settlement" like the nav.
- **Catalog (B2, part)**: the Destinations country filter lists the countries that have CIS places (geo countries with
  destinations > 0), the same source as the "Countries covered" tile.
- **Seasons page**: shows the last catalog sync's season step (assigned of picked, not in catalog, no destination,
  a cut read, degraded) and the tours still without a calendar. The fields are optional: before the B1 backend is
  deployed the panel stays hidden.

## Changed

Backend: `app/trip_cases/service.py` (`PARTY_AGENCY`), `app/catalog/lifecycle.py` (`tour_title`, `tour_label`),
`app/agency_billing/invoices.py` (`with_people_names`), `app/agency_billing/payments.py`.
Frontend: dashboard, cases list and detail, proposal and preview, staff, settings, invoice detail, agency billing,
destinations, readiness, tariff, trip plan detail and drawer, seasons; `ui/booking/{caseFacts,audit,plural}.ts`,
`lib/api/{types,agencyBilling,priceVersions}.ts`.

## Tradeoffs

- `party_agency_name` is a subquery per row (25 rows a page, indexed by `tenant_id`) rather than a join: the list keeps
  its count query and filters untouched.
- The lifecycle title adds up to two reads per event (catalog, then itinerary); events are rare (dozens a week).
