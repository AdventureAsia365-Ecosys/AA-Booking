# AA-972 (CRM-B1) — M2M auth and the B2B quote API

Linear AA-972 ("pool and scopes; offers; quote with FX lock and `price_hash`; parity flag; `b2b_price` naming, schema
test forbids `supplier_net`"). Sources: root ADR 0006b decision 7 (M2M pool), root ADR 0005a (B2B resale, naming),
contract `booking.b2b.v1` (root `docs/contracts/booking.b2b.v1.openapi.yaml`), the Booking commercial-core memo
(root `docs/audits/2026-10-22-S247-crm-w0/booking-commercial-core-memo.md`, seam rows 1, 6, 7, 9), design v3 §3.4, §5.1,
§5.2. Session S248, agent Claude Code.

## Decisions

- **Scope of this card** (memo "order that avoids rework" step 1): `b2b_partners`, `b2b_quotes` (+ lines), the M2M
  check, and the routes `GET /products`, `POST /quotes`, `GET /fx-rates`, `GET /price-parity` under
  `/booking/b2b/v1`. Departures, holds, confirm and cancel are AA-973 / AA-974; events AA-975. No trip case or version
  is created by a quote (memo seam 1).
- **Tables are plural** (`b2b_partners`, `b2b_quotes`, `b2b_quote_lines`) like every other Booking table; the design's
  singular names (`b2b_partner`, `b2b_quote`) are the same objects.
- **M2M verification reuses the vendored verifier unchanged.** The aa-m2m pool is one more `IssuerConfig`
  (`app.auth.m2m`): Cognito access-token profile (`token_use = access`, client in `client_id`), and
  `groups_claim = "scope"`, so the verifier's `Principal.groups` carries the space-separated `scope` claim, which
  `app.auth.m2m` splits. No second JWT decode, no edit of the byte copy.
- **401 vs 403.** No/garbled/expired/badly signed token, or a token of another issuer = 401 `unauthorized`. A token
  that is validly signed by the M2M pool but whose client is not configured for Booking, a missing scope, an unknown
  or suspended partner, or a client that is not the partner's `m2m_client_id` = 403 (Linear R: "wrong client or
  scope → 403"). The verifier raises `InvalidToken("client not allowed")` only after the signature, issuer and expiry
  checks passed (it decodes first, then checks the client), so mapping exactly that message to 403 is safe; a unit test
  runs the real verifier with a wrong client and fails if the vendored message ever changes.
- **Partner binding.** `X-AA-Tenant-Id` (UUID) must name an `active` row of `booking.b2b_partners`, and the token's
  `client_id` must equal that row's `m2m_client_id`: one CRM client acts for many agencies, but a second M2M client
  (another caller) can never quote for an agency that is not bound to it.
- **Configuration.** `COGNITO_M2M_ISSUER` and `COGNITO_M2M_CRM_CLIENT_ID` (env, set by AA-CIS-Infra `booking.tf` from
  the new pool and client, so no id is copied by hand). Empty = the B2B routes answer 503 `unavailable` (fail closed;
  nothing is accepted). Code constants stay empty on purpose: the pool does not exist until the Infra apply.
- **Components ("offers").** A product is a sellable `booking.trip_plans` row whose tour is in `catalog.v_tour` (live
  join, O7). Its bookable parts are the new `booking.trip_plan_components` rows (Booking-owned supply facts: a hotel
  room type or a service on a day of the plan), kept by staff with `PUT /booking/catalog/trip-plans/{source_id}/components`
  (`trip_plan.write`). Component ids are typed and opaque to the CRM: `rt:<room type uuid>` (kind `hotel_room`),
  `sv:<service uuid>` (kind = the service type: transfer, guide, activity, entrance, meal), and `tp:<trip plan uuid>`
  (kind `trip_plan`, the whole plan, listed only when the plan has at least one component).
- **Net cost of a line** comes from the supplier rate in force (bk-010, published contract, both validities) on the
  service day for the party size (adults + children; infants are not counted against pax bands or per-person
  units):
  - `hotel_room`: room nights x rooms; nights = `nights` (default 1), rooms = the sum of `rooms[].count` (default
    `ceil((adults + children) / 2)`); one rate per night looked up at each night's date, so a stay across a season
    change is priced per night;
  - service `person`: unit x (adults + children); `group` / `vehicle`: unit x 1; `day`: unit x `nights` (default 1);
  - `trip_plan`: the sum of every component of the plan, each on `service_date + day_no - 1`, a room component = one
    night for the line's rooms.
  - No rate in force for a line = 422 `invalid` naming the line (the CRM shows "ask AA"); no line is ever priced at 0.
- **Price.** The existing engine building blocks (`app.pricing.engine`: `to_usd`, `sell_price_usd`, `from_usd`) with
  the approved `b2b` rule in force on the quote day (seeded 15 % target / 10 % floor / 3 % card fee, "to confirm with
  Ms. Thư" — data in `booking.pricing_rules`, changed with maker-checker, not code). `peak = false` (no automatic
  peak calendar exists; staff set peak on B2C versions by hand). Each line's `b2b_price` = the line's selling price
  rounded **up to the cent** (never lowers the margin); `total_b2b_price` = the exact sum of the lines, so the CRM
  can add lines without a rounding mismatch. The B2C "round the total up to 5" rule is not applied to B2B prices:
  they are not customer-facing (the agency sets its own sell price). The rounding rule is recorded on the quote and
  covered by the hash.
- **Selling currencies**: the engine's existing five (USD, EUR, GBP, AUD, SGD). VND is AA-974 (bk-021).
- **FX lock.** One approved `fx_rates` row per non-USD currency, in force on the quote day, for the selling currency
  and every cost currency. The response's `fx.rate_per_usd` is the selling rate actually applied (`rate x (1 +
  buffer)`, 8 decimals); the plain rate, buffer, date and source are stored on the quote. USD quotes lock `1` with
  source `base`.
- **`price_hash`** = SHA-256 of a canonical JSON (sorted keys, no spaces) of: a version tag, the currency, the FX lock
  (plain rate, buffer, date, source), the rule (channel, margin applied, card fee, `valid_from`), the rounding rule
  and every line (line ref, component, service date, nights, pax, rooms, unit, availability, `b2b_price`) plus the
  total. It leaves out the quote id, `valid_until`, the proposal ref/version and the time, so the same request priced
  with the same data gives the same hash (all proposal formats share one hash; a changed price changes it).
- **Validity**: `valid_until = now + b2b_quote_valid_hours` (new `booking.settings` row, default 48, data not code).
- **Availability** is `available` for every priced line until AA-973 adds departures and capacity. A request line
  with a `departure_id` is refused (422 `invalid`, no departure exists before AA-973) rather than silently ignored.
- **Parity ("from" price, warn only, ADR 0005a decision 1).** `GET /price-parity` returns the plan's public "from"
  price per person from the bk-009 price hint when its basis is `per_person`, converted to the asked currency
  (hint currency → USD at the plain rate → asked currency with the selling buffer, rounded up to the cent); `null`
  when there is no per-person hint or no rate. A quote never fails or changes because a price is below it: the CRM
  compares its own sell price and warns.
- **`b2b_price`, never `supplier_net` (Fix B19).** The internal net is stored as `b2b_quote_lines.net_cost_usd`
  (`conf:commercial`) and never serialised. Response models are `extra="forbid"` Pydantic models mirroring the
  contract; a unit test walks the generated OpenAPI of every `/booking/b2b/v1` route and fails on any property named
  `supplier_net` or containing `net`/`cost`/`margin`, and on any route answering more keys than the contract lists.
- **Errors** follow the contract's `Problem` (`{error, message}`), not the staff `{detail, message}` shape: a
  `B2BError` with its own handler. Codes used here: `unauthorized` 401, `forbidden` / `unknown_partner` 403,
  `not_found` 404, `invalid` 422, `unavailable` 503.
- **Append-only quotes.** Role `booking` has SELECT, INSERT on `b2b_quotes` / `b2b_quote_lines` (no UPDATE, DELETE,
  TRUNCATE). A retention window for quotes is not set here (no personal data; volume is small on Dev); AA-825's job
  can take a kind later.
- **Partner admin** (`/booking/b2b-partners`, GET list, POST, PATCH status / name / billing currency / credit terms
  ref / client id): permission `b2b.admin` = Booking admin only. Every write adds one audit row (`entity_type =
  'b2b_partner'`). No delete (suspend instead).

- New modules `app/auth/m2m.py`, `app/b2b/` (errors, partners, products, quotes, parity), routers

## Tradeoffs

- **Components table now vs. later.** Without a link from a plan to supply items, `GET /products` would list plans
  with no bookable parts and `POST /quotes` could price nothing. A small Booking-owned link table (no content, ids
  only) is the least that makes the API usable; a staff UI for it is not in this card (API only, see Should know).
- **Per-line cent rounding vs. B2C 5-unit rounding.** Rounding every line up to 5 would add up to 5 USD to small
  lines (a 3 USD entrance becomes 5); rounding only the total breaks "sum of lines = total". Cent ceiling keeps both.
- **All four scopes on the CRM client.** The Infra client gets `read`, `quote`, `hold`, `book` now (one MFA round).
  Booking checks a scope per route, and the hold/book routes do not exist until AA-973, so the extra scopes grant
  nothing yet.
- **No retention kind for quotes yet**: rows hold no personal data; adding a kind is a later small change.

  settings list gains `b2b_quote_valid_hours`, the supply clean-up deletes plan components first) merges first; the

  a Booking deploy after it: before that they answer 503 `unavailable`.
- Nothing calls the API until AA-Partner (AA-933+) exists; live verification uses a client-credentials token minted
  with the CRM client's secret (handoff has the one-line commands) and a synthetic partner row.
- Staff UI for partners and plan components is not built here (API only); the Booking admin screens are a follow-up
  for the staff admin (AA-683 area).
- The B2B margin (15 %), floor (10 %) and card fee (3 %) are the bk-004 seed, still "to confirm with Ms. Thư"; change
  them as a new pricing rule row (maker-checker), no code change.
