# AA-993 — bk-034, the expand auto-apply proof file (S258)

The end-to-end proof of root ADR 0017 (M4b close-out): one Booking PR carrying an expand migration and the readiness
bump goes merge → copied by Migration Sync → merged by ci-bot → applied by Migration Apply → blocking Isolation Probe
green → Deploy Dev `schema-gate` passes → deploy → post-deploy verify, with no human step.

## Decisions

- **What bk-034 does:** a partial btree index `booking.trip_case_version_itinerary_source_tour_idx` on
  `trip_case_version_itinerary (source_tour_id) WHERE source_tour_id IS NOT NULL`. It is a real gap, not a no-op made
  for the proof: `app/catalog/lifecycle.py` `AFFECTED_CASES_SQL` (run by `bk_tour_lifecycle_pull` for each retired,
  paused or trashed CIS tour) matches a tour key three ways; legs (`trip_case_legs_tour_key_idx`) and the case key
  (`trip_cases_source_idx`) are indexed, the version itinerary is not (schema reference of 2026-10-29). The
  itinerary is the fastest-growing trip case table (one row per item per saved version).
- Considered and dropped: the unindexed `*_by` staff FKs (no read filters on them, staff rows are never deleted);
  `trip_plan_components (service_id / hotel_room_type_id)` (services and room types are never deleted, no read);
  `cancellation_policies (trip_plan_id)` (covered by the unique `(channel, trip_plan_id, valid_from)`); a `COMMENT ON`
  an existing object (not on the expand allow-list of ADR 0017 d3).
- **Expand shape:** header `-- migrate: expand`, one BEGIN … COMMIT block, `SET LOCAL lock_timeout = '5s'`, a plain
  (non-concurrent) `CREATE INDEX IF NOT EXISTS` because the table is ~4 rows (far under the 100k lock-risk limit), the
  registration last. No `DO` role guard (the expand lint refuses `DO` blocks as opaque); the runner's role switch
  applies it as `bk_owner`.
- **Readiness:** `backend/app/db.py` requires `bk-034`, so Deploy Dev's `schema-gate` must wait for the auto-apply;
  that wait is the thing the proof measures. Old code keeps working on the new schema (an index only).

## Changed

- `migrations/034_itinerary_source_tour_idx.sql`, `backend/app/db.py` (bk-034 required; bk-033 noted as no shape
  read), `backend/tests/integration/test_bk034_schema.py` (index shape, non-unique, valid, owner, re-run no-op).

## Tradeoffs

- Requiring bk-034 in readiness means a Deploy Dev of this commit fails at `schema-gate` (before rollout) if the
  auto-apply is off or broken; that is the intended behaviour (ADR 0017 d7) and the manual fallback is one DB Migrate
  apply, then a re-run of Deploy Dev.
