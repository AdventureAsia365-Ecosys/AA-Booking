# AA-1151 — Optional activities as AA add-on offers with places, sale rules and expiry alerts

Lane b-1151 of S289 (slice L8 of root `docs/audits/2026-11-19-S285-session/advisory-r2-plan.md`; advisories
`advisory-optional-activities.md`, `advisory-content-activities-hotels-critic.md`, `advisory-r2-b2b-crm.md` T7).
Migration bk-068 (migration-only PR first, MIG-4), then this code PR. The TripPlanner day cards, the CRM drawer and the
`booking.b2b.v1` add-on endpoint are the next slice (L9).

## Decisions

- **Option B of the advisory: a separate offer table**, one offer per service (`UNIQUE service_id`), places in their
  own table. Not a flag on `services`: a service has one place, and the sale rules are a commercial decision with its
  own second-person publish, not a supply fact.
- **Inventory stays in `supply_restrictions`** (bk-060). The offer holds no "free sale" or "stop-sale" column: T7's
  "free sale up to N" and stop-sale are restriction rows of the service, entered on its contract like a hotel's (critic
  point 3: one restriction model). "On request" is the engine default without a row. Allotment rows already exist.
- **Maker-checker like contracts (bk-064)**: `writers` kept by a trigger (the creator, each `updated_by` while a draft,
  and whoever adds a place: the places trigger touches the offer), `addon_offers_maker_checker_chk`, the generic owner
  self-approval guard in **mutable** mode (an offer can be reopened, which clears the flag; `published_at` is the
  recheck column). Reopening resets the writer list to the person who reopened, so someone else publishes the new
  version. Retiring is a single-person stop (it only removes something from sale).
- **Capabilities `addon.read` / `addon.write` / `addon.approve`**: content staff (`content_creator`) write drafts
  (B1: "AA content staff create and edit the activity"); only admin + contracting publish. `addon.approve` is approve
  class (custom roles never hold it). Every role reads (no net in any add-on response). The import needs
  `supply.write` too: it creates services, rates and a contract.
- **Publish gate**: active service and supplier, at least one place, an adult rate in force today or later under a
  published contract. Missing CIS customer text is shown (badge) but does not block: CIS publishes text on its own
  review flow, and the TripPlanner slice decides what to show without it.
- **Read model by day** (`v_place_addons`): one row per offer, place and day, over `addon_days_ahead` days. Done-when
  says "only days with an in-force price", which a per-day view states directly; the horizon is a Pricing > Policy
  value (the S279 rule), read by the view itself (no row in force = no rows, fail closed). No price column: B2 (agency
  page prices) is still open and prices are fixed at quote time; the reader quotes the `sv:` component.
- **Cut-off in the view is not applied** (only past days are dropped): the catalog has no time zone per place, so the
  exact closing time is decided at quote time; the view exposes `cutoff_hours` and `start_times`.
- **Quote rules (T7)** in `app/supply/addon_rules.py` (split from `addons.py` to avoid an import cycle with
  `app.b2b.components`): below the minimum, not a running weekday, or past the cut-off is 422 `invalid` with the reason
  in the message (no new contract field). Local start times are compared as UTC (documented approximation).
- **B4**: the offer's `child_pct` slots between the supplier child rate and the contract's child %, read in the same
  branch that reads the contract % (no extra query when no child needs it).
- **Expiry job**: `bk_contract_expiry_watch`, daily at 01:00 UTC like the departure watch, `notify_staff_once` keyed
  by `expiring:<valid_to>` (a renewed end date is announced again). The list endpoint is computed live, so the page
  shows the warning before the first job run. The window is `contract_expiry_alert_days` (seeded 60).
- **Reopen after retire (review fix)**: the writer list resets to the reopener only when the offer was published
  (its rules were approved). A draft retired before any publish keeps its writers on reopen and adds the reopener,
  else a second person's retire + reopen would let the only writer publish their own work (bk-068 trigger, DB and API
  tests).
- **Agent live check (review fix, root ADR 0006a A10e-4)**: the A10e-2 pricing maker may also import the activity
  catalogue of its synthetic supplier (supplier checked from the path; the route refuses an unmarked title or
  inclusions text, `e2e_staff.check_activity_sheet`). The pricing checker publishes the contract (A10e-3); the A10h E2E
  owner, who wrote none of it, publishes the offers. No allow-list entry for the offer writes themselves.
- **Contract expiry pill (review fix)**: one `warning` tone for every expiring contract. The only threshold is the
  policy window `contract_expiry_alert_days`; an earlier draft had a second, hard-coded 14-day "danger" cut-over.
- **Importer**: a separate workbook (Contract + Activities) instead of more columns on the rate sheet: the rate sheet
  prices existing items; this one creates them. Places by CIS id or exact name (ambiguous names ask for the id).

## Changed

- `price_lines` passes the offer child % through `_lookup` (fourth return value) and `_split_cost`.
- `quote_in` calls `check_addon_rules` before pricing (one query when the quote has an `sv:` line).
- `/booking/contracts/expiring` is registered before the suppliers router (else `/contracts/{id}` would take it).

## Tradeoffs

- No outbox event for offers yet: TripPlanner reads the view live; CIS needs no offer facts (it writes per service).
- No CIS `customer_title` / `locale` columns (advisory section 5): the TripPlanner slice needs them, this slice does not.
- No allotment consumption for add-ons: free sale and allotment show in the view, the B2B engine still answers
  on request for `sv:` lines without a departure (bk-060 note).
