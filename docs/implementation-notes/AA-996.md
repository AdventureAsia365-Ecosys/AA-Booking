# AA-996 — Booking covers every Figma screen

Linear AA-996 (Nghiệp's decision S253, memory "booking-figma-full-coverage"): build every Figma screen of the Booking
staff admin; the CIS-owned parts are read-only with an "Edit in CIS" link. Sources: `docs/ui-spec.md` §3 (route map,
modal table, the former "deliberately not built" table), the 120 PNG exports in `AA-Ecosys/docs/AAA/figma_AAA/`, the
module specs in `AA-Ecosys/docs/audits/2026-10-14-S236-design-review/booking-ui-spec/`. Session S254, agent Claude Code
(lane, orchestrated).

Order of work (one commit each): 1 coverage matrix, 2 Sign-in & security, 3 soft-delete dialogs, 4 CIS-owned content
forms, 5 Destinations and Countries pages (+ API + migration), 6 ui-spec update.

## Decisions

- **Coverage matrix first** (`docs/figma-coverage.md`): one row per PNG, built by a script that refuses a file without
  a row, so nothing is skipped. Statuses: built / new (AA-996) / replaced-by / duplicate-misfiled. Misnamed exports
  (COUNTRY MANAGAMENT-2/-3 = hotels, DELETE SUPPLIER = Delete User on customers, SEND REMAINDER = Cancel invoice
  frame) map to the route that covers what they really show; the module specs' "actually shows" tables are the source.
- **DELETE TRIP = Make not sellable.** The frame is drawn over the Trip Templates list (spec 03 S6), so its Booking
  equivalent is the trip plan's sellable flag, not a trip case (a case is cancelled through its status menu, which
  already exists).

- **Sign-in & security is a Settings tab** (`/settings?tab=security`), not a new route: Figma puts change password in
  Settings (SETTINGS-2). Facts come from a new BFF route `GET /api/auth/session` (`lib/sessionFacts.ts`): kind of
  sign-in, signed-in time (Cognito `auth_time`), session end (the 12 h refresh window stored in front of the refresh
  token in `bk_staff_rt`). It is under `/api` because the refresh cookie is path-scoped there. It returns times and
  the kind only, never a token.
- **MFA wording states the fact** (review fix): per root ADR 0006 WORKFORCE MFA is optional, TOTP only and used only
  by break-glass, so staff have no second factor; the page says "None: the one-time e-mail code is the sign-in factor".
  The first draft ("Managed by the company sign-in … managed in CIS") claimed something the system does not do (MFA is
  a Cognito pool setting in Terraform, not a CIS screen).
- **CIS staff page** = `CIS_STAFF_PATH` `/admin/platform/staff` (exists in AA-CIS-App `frontend/app/admin/platform/
  staff/page.tsx`). Staff list: page action "Manage staff & invites in CIS ↗" + a per-row key icon link (Figma
  RESET PASSWORD / Invite) to the per-person CIS page `/admin/platform/staff/<cis_user_id>` (AA-883 deep link; its id
  is the same cis_user_id, CIS `bookingStaffUrl(id)` links back). The staff detail page uses the same per-person link.
  Settings → Sign-in & security shows the CIS staff link only to `staff.admin` (CIS → Platform → Staff is admin-only);
  other roles read "Ask a Booking admin …".

- **Soft-delete dialogs = one component in the Figma layout.** `ui/booking/ConfirmDialog.tsx` (used by every
  deactivate / archive / cancel / void / delete-draft dialog) now draws the Figma frame: round warning icon, title and
  message beside it, footer band with Cancel + action, no header bar. So every existing soft-delete dialog (hotel,
  service, supplier, customer archive, staff deactivate, delete draft, cancel invoice, void payment) took the layout
  at once. Existing endpoints: hotels / services / suppliers `…/deactivate|activate`, `DELETE /customers/{ref}`
  (archive), `DELETE …/versions/{n}` (soft), invoice cancel, payment void, `PATCH /staff/{id}` (active).
- **New soft endpoints only where none existed**: country and destination status (`PATCH /booking/catalog/geo/…`) and
  "Make not sellable" (no endpoint needed: `PUT …/trip-plans/{id}/commercial` with `sellable=false`; the dialog reads
  the plan first so the other commercial fields are sent back unchanged, PUT clears absent fields).
- **Migration bk-029 was unavoidable**: the countries / destinations status must persist and `booking.countries` is
  read-only for role `booking` (bk-005 REVOKE). Two small tables, no delete grant. `bk-029` was earmarked in the
  AA-682 design for supplier bills (S4) but no file exists yet; whichever lands second renumbers.
- **New permission `catalog.admin` (admin only)** for the geo status / notes edits: UI spec §3 says "A edit status".
  Reads stay on `catalog.read` (every role, content creators included).

- **CIS-owned form parts = one block** (`app/(staff)/_parts/CisFields.tsx`: `CisFieldset` + `CisField`): read-only
  inputs with a lock, "From CIS" tag, "Edit in CIS ↗" only for roles that edit content in CIS (admin, content creator,
  the existing `CIS_EDITOR_ROLES` rule). Used by the trip plan commercial drawer (tour title, SKU, country, duration,
  days, summary → `/admin/master-content?tour=<tour_id>`), the service form (CIS supply content status, highlights,
  description → the CIS-served `edit_url`; on add, a note that CIS drafts it after the save), and the destination /
  country drawers (→ `/admin/places`: CIS has no per-place or country editor page, checked in AA-CIS-App
  `frontend/app/admin`).
- **"Add country" / "Add destination"** do not create content: Add country picks an ISO country Booking does not list
  yet and stores Booking state for it; Add destination picks an existing CIS place and opens its Booking state.
  Review fix: `update_country` writes the profile row of an unlisted country (no CIS place, no CIS tour, no profile)
  even when the body keeps every default, audited as `country.added` (before = null, after = the full state), so
  "Save country" with the defaults lists the country; a no-op PATCH on a listed country still writes nothing.
- **Concurrent edits** (review fix): `update_country` / `update_destination` take a per-key transaction advisory lock
  (`pg_advisory_xact_lock(hashtext(table), hashtext(key))`) before the read-merge-upsert, so two admins editing
  different fields of the same row serialize instead of overwriting each other (and the audit matches the stored
  state). Advisory, not `FOR UPDATE`, because the first write of a key has no row to lock; the two-key form keeps it
  apart from the one-key outbox lock.
- **Country search** matches the ISO code only for a two-letter query ("vn"); a longer word is a name match only (the
  first draft compared the first two letters of any query, so "Myanmar" also found MY Malaysia).

- **Destinations list** is server-paged (`limit`/`offset`, 25/50/100) and filtered on the server (lesson: list pages
  page and filter server-side); the KPI summary counts the whole catalog. **Countries** is a short derived list (one
  per ISO country with a CIS place or tour, or with Booking state), so it is returned whole and drawn as the Figma
  card grid; filters still run on the server.
- **Country detail tabs** show the true counts (`destinations` / `tours`) and, when the capped item list (200 places /
  50 tours) is shorter, "Showing the first N of M. See all …" linking to the server-paged list filtered by the country
  (`/catalog/destinations?country=<ISO>`, `/catalog/trip-plans?country=<name>`).
- **Country detail** is a page (`/catalog/countries/[iso]`), the Figma drawer variant (COUNTRY DETAILS) is folded in
  (spec 06 recommendation): tabs Overview / Destinations / Tours. Destination detail is a drawer (`?place=<id>`).
- **Tour counts per destination are not shown**: the only per-place tour source is `catalog.v_tour_place`, which
  parses every tour's itinerary per call (lessons log, "Dữ liệu": ~0.9 s per call). Per-place Booking supply counts (active suppliers,
  hotels, services) are shown instead; tour counts are per country (`v_tour.country`).

## Tradeoffs

- **Role gates** (review fixes): the country drawer opens from `?edit=` only for `catalog.admin`; the service form's
  "Edit in CIS ↗" shows only for `CIS_EDITOR_ROLES` (others read "Ask the content team…"), like every other CIS block.
  The geo Deactivate reason is capped at 500 characters in the dialog (`ConfirmDialog` `reason.maxLength`), matching
  the API and the bk-029 CHECK.
- **Kit `danger` button (soft red) instead of Figma's solid red** in the dialogs: the button is the vendored CIS kit
  (`ui/primitives.tsx`, byte-comparable with CIS); a solid variant belongs in the CIS kit first.
- **No vitest**: the Booking frontend has no unit-test runner (only Playwright layout-mock and smoke-public, plus
  eslint / tsc / next build in CI). Adding vitest means a new devDependency and lockfile change outside this issue;
  the frontend behaviour is covered by the layout-mock page cases instead, the API by pytest (unit + integration).
- **Status is informational in this slice**: an inactive country or place is shown and filtered everywhere it is
  listed, but it does not yet block a supplier place pick, a hotel / service place or a proposal item. Blocking would
  change existing flows (suppliers, B2B products) and needs its own decision.
- **Countries are matched by name** (`v_destination.country` / `v_tour.country` are names, CIS 225): a CIS name that
  has no row in `booking.countries` is reported as "unmapped" (KPI tile) instead of being guessed.
- **No per-place tour count** (see Decisions: `v_tour_place` cost).

## Fix after the first Dev check (countries mapping, images)

Live on Dev, Catalog → Countries showed 13 countries, "CIS places without a country: 293 — Kyrgyzstan, Pakistan,
Taiwan", and "Images 0" on every card.

- **Root cause, countries.** The list started from `booking.countries` (bk-005 seed of 16 markets + Mongolia from
  bk-008) and matched place / tour country *names* to it. Pakistan, Taiwan and Kyrgyzstan are real CIS countries
  (CIS 288: a tour's country is any ISO country) with no row there, so their places counted as "without a country" and
  the countries never appeared. Not a spelling problem.
- **Decision.** Countries come from CIS: `catalog.v_country` (CIS 279, every ISO 3166-1 entry, granted to booking);
  places group by `catalog.v_destination.country_iso2` (CIS resolves it, aliases included); tours by
  `v_tour.country` = `v_country.name` (CIS 288 makes the tour country a `shared.countries.name`). "Places without a
  country" = places whose `country_iso2` is NULL (CIS could not resolve them), which is CIS's orphan report.
- **No migration.** `booking.country_profiles.country_code` references `booking.countries`, read-only for role
  booking. A CIS country outside it is listed and readable but carries `booking_reference = false`; the UI hides
  Edit / Deactivate for it and `PATCH` answers 409 `country_not_in_booking` (instead of a foreign-key 500). Letting
  staff keep state for those countries needs a later bk-NNN that extends `booking.countries` (it also gates
  suppliers and trip case countries).
- **Root cause, images.** The count summed `v_destination.photo_count`, i.e. only photos tied to a place
  (`place_photo.destination_id`). On Dev the AA photo library is matched to tours, not places, so every country read 0.
- **Decision, images.** Images of a country = `count(DISTINCT path)` over its places' photos
  (`v_destination_photo`, place's `country_iso2`) plus its tours' photos with no place (`v_tour_photo` where
  `destination_id IS NULL`, the tour's country). Distinct `path` because CIS 290 points every copy of one file at one
  path. A tour photo tied to a place counts for the place's country (cross-border places are not double-counted).
  Separate query, fails soft to 0 (logged) like the destination photo list.
- **Not changed.** `app/catalog/destinations.py` (supplier place picker) still maps names through `booking.countries`
  on purpose: its `country_code` feeds `booking.suppliers.country_code`, which references `booking.countries`.
  Per-place `photo_count` on the Destinations list is CIS's value (place-tied photos only).

## bk-031: the missing CIS tour countries (S254)

### Decisions

- **Which rows.** The AA tour countries of CIS (CIS migration 279 checks that each resolves: Bhutan, Cambodia, China,
  India, Indonesia, Japan, Kyrgyzstan, Laos, Malaysia, Mongolia, Myanmar, Nepal, Pakistan, Philippines, South Korea,
  Sri Lanka, Taiwan, Thailand, Uzbekistan, Vietnam) minus the 17 rows already in `booking.countries` = **KG, PK, TW,
  UZ**. Uzbekistan has no CIS place on Dev yet (Dev showed only Kyrgyzstan, Pakistan, Taiwan as read-only) but it is
  an AA tour country, so it is added with the others instead of in a later file.
- **Names = CIS `shared.countries.name`** (`Taiwan`, not the ISO "Taiwan, Province of China"): Booking matches CIS
  country names to this table by name (`app/catalog/destinations.py` supplier place picker, `app/catalog/trip_plans.py`).
- **active = true**: AA sells these countries (as for Mongolia in bk-008), so they show in the country pickers.
- **Static rows, not `SELECT … FROM catalog.v_country`**: a Booking migration does not read another app's schema
  (the guard allows reads of `shared.schema_versions` only), and a fixed list is reviewable.
- **Not in `REQUIRED_SCHEMA_VERSIONS`**: the code works before and after the file; until it is applied the four
  countries stay read-only, as today.

### Changed

- No application code: `booking_reference` is `booking.countries` membership, so it turns true by itself.
- Tests: `test_bk031_schema.py` (rows, names = the CIS view, re-run no-op, never overwrites, `booking` still reads
  only); `test_bk029_geo_api.py` now expects Pakistan to be editable and keeps the 409 `country_not_in_booking` case
  with a stub country still outside the list (Kazakhstan, added to `stub_catalog.sql` `catalog.v_country` with UZ).
