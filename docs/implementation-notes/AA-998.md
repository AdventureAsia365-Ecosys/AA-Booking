# AA-998 — no account labels on admin pages (rule R1), Booking

## Decisions
- The retention run result (stored as the `after` of its `booking.audit_logs` row, rendered by the staff Audit log
  page) used to name the archive bucket `aa-cis-bronze-<acc2>`. A live run that archives now records the real bucket
  it wrote to (`S3Archiver.bucket`, built from the STS account of the running task by `default_bucket`, cached once
  per process), so the page shows the account ID at runtime and the repo holds none.
- Dry runs and `GET /booking/retention` never resolve the bucket (no STS call without an archive); they show the
  neutral placeholder `aa-cis-bronze-<account-id>` (`ARCHIVE_BUCKET_DISPLAY`).

## Changed
- `app/retention/policy.py`: `ARCHIVE_BUCKET_DISPLAY` placeholder `<acc2>` -> `<account-id>`.
- `app/retention/jobs.py`: live archiving run sets `result["archive"]` from the archiver's bucket.
- Tests: unit placeholder value; integration `test_bk012_retention` pins the live audit row to the test bucket.

## Tradeoffs
- Calling STS in dry runs would show the ID there too, but adds a network call to a path that writes nothing; the
  placeholder already carries no label.

## Should know
- Audit rows written before this change still contain `<acc2>` in `after.archive` (history, not rewritten).
- No account ID is in the repo: tests use `aa-cis-bronze-test` / `111111111111`.
