# AA-810 — Minimal pricing engine (ADR 0005 first cut)

Scope (S236): a pure pricing module (`backend/app/pricing/engine.py`), migration `bk-004`
(`pricing_rules`, `fx_rates`, `version_item_costs`), a repository and `POST /booking/pricing/quote-preview`.
Source of truth: root ADR 0005 "Pricing and supplier rates" (decisions 2, 4, 5 and 8).

## Decisions

- **Formula.** `sell_usd = net_usd / (1 - margin - card_fee)`. The margin is a gross margin on the selling price
  (ADR 0005 d4, not markup). The card fee (~3%) is "built into the price, not a surcharge"; it is modelled as a
  share of the selling price next to the margin, so after paying the fee AA keeps exactly `margin` of the price.
  Example: 700 USD net, B2C 30%, fee 3% → 700 / 0.67 = 1,044.78 → **1,045 USD**.
- **Peak.** `margin = target + peak_uplift_pts` when the request says `peak: true` (ADR: +3 to +5 points). The
  seed uses 0.03 (low end). Season detection (which dates are peak) is not in this slice: staff set the flag.
- **FX.** Costs convert to USD at the plain dated rate (`net / rate_per_usd`), no buffer. Selling in EUR/GBP/AUD/SGD
  = `sell_usd × rate × (1 + buffer_pct)` (ADR d5). The buffer lives on the `fx_rates` row (one row per currency per
  `as_of`), and only applies when that currency is the selling currency.
- **Rounding.** Only the quote total is rounded, once, **up** (ceiling) to the currency increment: USD 5 (ADR), and
  5 units for EUR/GBP/AUD/SGD too (open question). Ceiling, not half-up, so rounding never lowers the margin under
  the computed one. Lines are shown unrounded (cents) and `subtotal` is their sum.
- **Floor.** `effective_margin = 1 - card_fee - net_total_usd / total_usd`, `total_usd` = the final total converted
  back at the plain rate (no buffer: the margin AA really earns at today's rate). `below_floor = effective_margin <
  floor_margin` (the floor itself is allowed). A computed total is never below the floor (target ≥ floor and
  rounding goes up), so the flag matters for `override_total`, a sales override of the total; it is never rounded.
  Recording the override reason and auditing it come with the quote slice (nothing is written here).
- **Rule/FX in force** = newest row with `valid_from` / `as_of` ≤ today (UTC). The response returns the rule's
  `valid_from` and every FX rate's `as_of` and `source`, so staff can see a stale rate.
- **Append-only policy tables.** `pricing_rules` and `fx_rates`: role `booking` has SELECT, INSERT only (ADR d2:
  "new rows with new validity — never overwrite"). bk-004 grants per table instead of the usual
  `GRANT ... ON ALL TABLES` so it does not re-open UPDATE on them.
- **Seed.** ADR 0005 table: 30/20 (B2C tailor-made), 25/18 (fixed departure), 15/10 (B2B), peak 0.03 and card fee
  0.03 on all three, `valid_from = 2026-10-14`, note "to confirm with Ms. Thư". No FX rows (market data).
- **Staff ids are TEXT** (`booking.staff_users.cis_user_id`, the CIS JWT `sub`) — aligned with the AA-681 slice 3
  lane's bk-003 rather than the task brief's `uuid`. `created_by` / `entered_by` reference `staff_users`.
- **Approval lock on costs.** `version_item_costs` gets the same lock as bk-003 version items (a trigger function
  `booking.version_item_cost_lock()`, `SET search_path = pg_catalog`, not SECURITY DEFINER): once the version is
  approved, its cost rows cannot be inserted, updated or deleted.
- **Who may call quote-preview:** permission `pricing.read` in the staff role matrix (`app/auth/staff.py`):
  `admin`, `sales`, `contracting` (403 for `content_creator`): margins and net costs are commercial data (ADR d8).
- **Money in JSON** is a string (Pydantic v2 `Decimal` serialisation); amounts accept strings or numbers, at most
  2 decimals, `net_amount ≥ 0`, `override_total > 0`, 1–200 items, ISO upper-case currency codes.

## Changed

- Brief said `created_by`/`entered_by` uuid; they are TEXT FKs to `booking.staff_users (cis_user_id)` (bk-003).
- Brief listed `version_item_costs` columns only; added `created_at`/`updated_at`, an index on `version_item_id`,
  `ON DELETE CASCADE` from the item, and the approval lock.
- Added `note` to `pricing_rules` (for "to confirm" / change reasons) and CHECKs (ratios in [0,1), floor ≤ target,
  target + uplift + fee < 1; FX rate > 0, buffer in [0,1), no USD row, non-blank source).
- `override_total` (optional) added to the request so `below_floor` is meaningful.
- `REQUIRED_SCHEMA_VERSION` was bumped to `bk-004`; after the rebase it is `bk-005` (the highest migration).
- Migration guard: the same `"or"` trigger-event fix as the AA-681 slice 3 lane (`BEFORE INSERT OR UPDATE OR
  DELETE ON` is not DML), applied byte-identically so both branches merge cleanly.

## Tradeoffs

- Card fee as a share of price (`/(1 - m - f)`) vs a second division (`/(1-m)/(1-f)`): for 700 USD net at 30% / 3%
  the first gives 1,044.78, the second 1,030.93. The first keeps "margin = m of the selling price after the fee";
  the second keeps m only on the price net of the fee. Chosen: the first, matching the ADR's "margin on the selling
  price" with the fee as a cost inside that price. Open question for Ms. Thư.
- Rounding increments are a code constant (`ROUNDING_INCREMENTS`), not a table: they are presentation rules with one
  value today; move them to data if Ms. Thư wants per-market rules.
- Rounding only the total (not each line) avoids inflating multi-line quotes by up to 4.99 per line.
- No FX staleness limit: the endpoint shows `as_of` instead of refusing old rates (no business rule yet).
