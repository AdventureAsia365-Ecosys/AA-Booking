# AA-1008 — Booking admin on the kit ShellFrame, visual job, empty suppressions (Booking part)

Lane l3 of S269 (Claude Code). The ShellFrame, the Tabs roles and the decisions behind them are in AA-CIS-App
`docs/implementation-notes/AA-1008.md` (the canonical kit repo). This file covers the Booking consumer side. H3
(required checks in branch protection) is not in this lane: it needs the tech lead's GitHub sign-in.

## Decisions

- **AdminShell is the Booking configuration of ShellFrame.** `ui/local/AdminShell.tsx` passes the existing Sidebar,
  Topbar, BottomNav and CommandPalette as slots (`drawerBelow={768}`, `main="page"`: every page renders its own
  PageFrame). The ⌘K handler, the Esc handler, the drawer state and the drawer CSS (`.aa-admin-sidebar--open`,
  `.aa-admin-backdrop`, the fixed hamburger) are gone from Booking: ShellFrame owns them. The "no access" state now
  renders inside a PageFrame, so it has the kit frame like every other page.
- **Visual run per PR = `next start` with the AA-910 layout-mock API**, not a Vercel preview (ADR 0019 d23) and not
  the Dev API: staff pages get the unsigned session cookie the layout check uses (proxy.ts only decodes it), their
  `/api/booking/*` calls are answered from `e2e/layout/fixtures.ts`, the clock is frozen. A call without a fixture is a
  finding ("unmocked"), so a new page cannot pass by rendering an error state. Production auth is unchanged.
- **After the production deploy: public pages only** (login, 404) on `https://booking.lumiguides.it.com`, job
  `visual-production` of `vercel-deploy.yml` (report-only, the `result` verdict does not wait on it). Booking has no
  Cognito E2E sign-in from CI yet, so staff pages are covered by the per-PR mocked run.
- **Gated kit gallery route** `app/kit-gallery` (404 unless the server runs with `KIT_GALLERY=1`) carries the
  self-test: `?plant=overflow` (a strip in the document) and `?plant=frame` (a strip inside the PageFrame). The
  workflow's self-test step must see the Playwright run fail and `summary.mjs --selftest` must find all 8 planted
  captures caught.
- **Suppressions:** the four `aa-kit/no-hex-colour` entries were arbitrary `rgba()` shadows; they now use the kit
  elevation tokens as Tailwind utilities (`--shadow-kit-sm|md|lg` = `--aa-shadow-*` in `globals.css`). The file is `{}`.
- **G16 guard** `ui/booking/visualPages.test.mjs` (runs in `npm run test:unit`): every `app/**/page.tsx` route is in
  `e2e/visual/pages.ts` or in `EXCLUDED` with a reason, plus the changed-pages and page-selection rules.

- **Overflow probe compares with the configured viewport width** (not `window.innerWidth`, which a 390 px mobile
  emulation widens to an overflowing page's content); a redirect answer is not a failed request. Same fix in CIS and
  AA-Partner (the AA-Partner run found a real 12 px overflow that the old probe passed).

## Changed (vs the issue)

- The issue named "PR previews"; the per-PR run uses `next start` in the runner (Linear re-scope of S265, ADR 0019).
- Eight write / version routes are excluded (`EXCLUDED` in `e2e/visual/pages.ts`): the layout mock answers reads
  only, or has no fixture for them yet.
- The visual job is report-only until H3.

## Tradeoffs

- Mocked staff pages show fixture data, not Dev data: stable and free of secrets, but a layout bug that only real
  data triggers is caught by the AA-910 layout check or by hand, not here.
- `kit-gallery` lives in the production bundle (it answers 404 there): the same pattern as CIS; the cost is one small
  route.
