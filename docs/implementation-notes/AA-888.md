# AA-888 — Docs lint in AA-Booking

Scope of this PR (S245 lane): bring the docs-lint checks that run in the AA-Ecosys root repo (root PR #105) to this
repo, plus the weekly freshness report. The ADR index (`docs/adr/README.md`, PR #42) and the blocking resource-ID
check (AA-902, "Security Audit") were already here.

## Decisions

- **Vendored tools, not a reusable workflow.** `tools/docs/` is a copy of AA-Ecosys `tools/docs/` and the schema a
  copy of `docs/templates/frontmatter.schema.json`. The root repo is private, so this public repo's CI cannot check
  it out or call a reusable workflow from it without a cross-repo token. The copies are byte-identical with
  AA-CIS-Infra (only `tools/docs/README.md` differs). They are not yet identical with AA-Ecosys `origin/master`:
  `docslib.py`, `check_docs_text.py`, `check_frontmatter.py` and `test_docs_tools.py` carry the additions below,
  which go back to the root in AA-Ecosys branch `ci/aa888-docs-tools-sync`; after it merges, all three copies of
  the seven files are identical (checked with `cmp`). The README says how to keep them equal.
- **Three backwards-compatible additions to the tools**, made here first and meant to go back to the root so all
  copies stay identical: `check_docs_text.py --all` (every tracked Markdown file minus journals: this repo keeps
  pages at the root, outside the root repo's `docs/ skill/ .kiro/ .claude/` scope), `--block KINDS` (used by Infra),
  and `CONTEXT.md` in the front-matter scope (the root repo has no root `CONTEXT.md`, so nothing changes there).
- **Fake IDs in `test_docs_tools.py` are assembled at run time** (`"sg-" + "0123..."`). The AA-902 check scans every
  tracked file here and would otherwise fail on the test fixtures.
- **No resource-ID step in the docs job.** "Security Audit" already blocks literal IDs in every tracked file
  (stricter than the docs regex: also code, YAML, after `-`). Running the docs variant too would double-report.
- **No path filter** on `pull_request`, so the "Docs lint" check reports on every PR and can be made required.
  Public repo: Actions minutes are free; the job takes under a minute.
- **Action pins** reuse the root workflow's commit SHAs (checkout v7.0.1, setup-python v7.0.0, lychee-action
  v2.9.0, upload-artifact v7.0.1). Dependabot's weekly github-actions group updates them.
- **Schedule** Mondays 01:23 UTC, a few minutes after the root run (01:17), so the three weekly reports land together.

## Changed

- New: `.github/workflows/docs-lint.yml` (jobs "Docs lint" on PRs and dispatch, "Docs freshness report" weekly and
  on dispatch), `tools/docs/*`, `docs/templates/frontmatter.schema.json`.
- `CONTEXT.md` layout block lists the workflow, `tools/docs/` and `docs/templates/`.
- Not done: markdownlint (warn-only in root, not part of the issue's "smaller job"), gitleaks (already in
  "Security Audit" on the full history).

## Tradeoffs

- Copies can drift. Accepted over a cross-repo token (a secret in a public repo's CI for a lint job). Mitigation:
  README rule "change the root first, copy to both repos in the same session"; the root PR that takes back the three
  additions makes the copies identical again.
- `--all` scans `README.md`, `CONTEXT.md`, `.claude/CLAUDE.md`, `frontend/README.md` and the PR template, which
  the root default scope would not reach. Journals (`docs/implementation-notes/`) stay out, as in root.

## Should know

- Done-when evidence: branch `test/docs-lint-red` adds a page with a fake `sg-` ID and a backslash-continued `aws`
  command. Expected: "Security Audit" fails (AA-902, the `sg-` ID) and "Docs lint" fails ("Single-line AWS CLI").
  That branch is never merged; close its PR after the red run.
- "Docs lint" is not a required check until someone adds it in branch protection (owner action).
- The first scheduled freshness run is the Monday after merge; `workflow_dispatch` produces one at once.
