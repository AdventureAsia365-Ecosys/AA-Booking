# AA-1175 / AA-1158, lane e-e2e-a10e6: E2E pricing pair decides band changes and synthetic bills (root ADR 0006a A10e-6)

S290 (24/11/2026). The tech lead approved A10e-6 in S290 (close-out plan decisions D2(b) and D3(a)): the agent's
live checks for AA-1175 (a group-size band change needs a second person) and AA-1158 (payout rules need a bill
entered by one person and approved by another) must run with E2E identities, not hand steps.

## Decisions

- **Three new writes, no more.** Checker: POST `/booking/pricing/policy/{version_id}/approve` and `/reject`, POST
  `/booking/supplier-bills/{bill}/approve`. Maker: POST `/booking/supplier-bills`. Submit, withdraw and discard of a
  policy, propose, bill edit / cancel / payouts and void stay 403 `e2e_read_only` for both identities.
- **Policy decision scope.** Only a `price_pax_bands` version whose `created_by` is the A10h E2E owner's staff row
  (`e2e_owner.E2E_OWNER_EMAIL`). The key is bound as `$3`, never written into the SQL (gitleaks generic-api-key
  pattern on `key = '...'`, S278). A unit test keeps `POLICY_PARAM == pax_bands.KEY`.
- **Bill entry scope.** The body's supplier is the maker's synthetic supplier (A10e-3 SQL) and the body's trip case
  (UUID or `TC-` code) belongs to an agency whose `catalog.v_tenant_account_v1.is_synthetic` is true. The lines are not
  checked by the guard: the bk-045 trigger `supplier_bill_items_guard` refuses a line of another supplier or another
  trip case than the bill.
- **Bill body.** Bill number starts `SYNTHETIC` (like the desk entry's agency reference), a non-empty `trip_case`, no
  `departure` key (a departure bill has no agency), `notes` absent or null (no free text from an E2E identity), lines
  exactly `{supplier_booking_id, amount}`.
- **Bill approval scope.** The bill's `created_by` and `facts_edited_by` are both the maker (so a bill someone else
  edited is never approved by the checker), its supplier is the maker's synthetic supplier, its trip case a synthetic
  agency's. By UUID or `BIL-` code.
- **Policy reject body.** The route needs a reason; the E2E reason must start `SYNTHETIC` (marked text only).
- **New module `app/auth/e2e_staff_finance.py`.** `e2e_staff.py` is near the 800-line file cap (776 now); the checks
  live beside it like `e2e_staff_supply.py`, dispatched through a new set `FINANCE_CHECKED`.
- **No grant.** `contracting` already holds `bill.write`, `bill.approve` and `pricing_policy.approve` (the approver
  permission of the `pricing` group that `price_pax_bands` belongs to).

## Changed

- `backend/app/auth/e2e_staff.py`: route constants, the maker / checker allow-lists, `BODY_CHECKS` entries,
  `FINANCE_CHECKED`, the dispatch in `is_synthetic_record`.
- `backend/app/auth/e2e_staff_bodies.py`: `policy_reject_body_ok`, `bill_body_ok`.
- `backend/app/auth/e2e_staff_finance.py` (new): `POLICY_SQL`, `CASE_SQL`, `BILL_SQL` and `check_record`.
- Tests: `tests/unit/test_aa1087_e2e_writers.py` (the reviewed allow-list and the "checked exactly one way" partition),
  `tests/unit/test_aa1175_e2e_policy_bills.py`, `tests/integration/test_aa1175_e2e_policy_bills.py`.
- `CONTEXT.md`: the A10e-6 paragraph.

## Tradeoffs

- Giving the E2E owner the checker role instead was refused: A10h D6 says the owner is never the checker, and the
  owner may only be the maker. A fourth identity would need an Infra trigger entry, a Cognito user and a Terraform
  Apply for three writes.
- Checking each bill line in the guard was not done: the database trigger already holds every line to the bill's
  supplier and trip case, and both of those are checked.

## Should know

- Exposure: whoever reads the checker's code can approve or reject a pending band change the E2E owner proposed. An
  approved band change reprices every plan with components on Dev at the next recompute (the close-out plan restores
  the old bands right after). Whoever reads the maker's code can enter bills (received, unpaid) for the synthetic
  supplier on a synthetic agency's case; the checker can approve them. Nobody here can record a payout
  (`payout.write` is admin only).
- Removed with the A10 family at go-live (AA-1054): drop the four writes, `e2e_staff_finance.py`, the two body checks
  and the tests.
