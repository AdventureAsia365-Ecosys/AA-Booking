# AA-1030 G3 — Agency tariff export (Booking side)

Lane l12 of S269. Extra scope G3 of AA-1030, approved by the tech lead in S269 from the research note (root
`docs/research/2026-11-05-asian-trails-b2b-benchmark/README.md`, "Gaps worth adding to R4"): a per-agency tariff, the
agency's own price per tour, season and pax band, as CSV and a printable page, for staff (pick a partner) and for the
agency itself through `booking.b2b.v1` (its own prices only; additive minor). Stacked on lane l9
(`feat/aa-1030-agency-price-tiers`, tiers and rate cards, bk-043). No migration.

## Decisions

- **The price is the quote engine's, not the matrix amount.** The brief asked for the tariff "from the price matrix"
  and "equal to what the quote engine would charge". In Booking these are two different numbers today: the matrix's
  b2b `amount` is a per-person price rounded up to 5 USD with the peak uplift (the cost sheet, AA-1029, used for the
  RRP and the public "from" price), while `POST /quotes` never reads the matrix: it prices the plan's components at the
  supplier rates in force, with no peak uplift, rounded up to the cent per line. A tariff built on the matrix amount
  would not match the quotes the agency then gets. So the matrix gives the **grid** (each b2b row still valid: season,
  window, pax band) and every row is priced by the quote engine itself.
- **No duplicated math.** `app.b2b.quotes` now exposes `PriceBasis` (rule, FX, FX lock, agency terms on a day),
  `price_basis()` and `price_line()` (nets → USD → rule price → agency discount → `round_line`); `create_quote` calls
  them (same order of reads and errors as before) and `app.b2b.tariff` calls the same two plus `components.price_lines`
  for the plan's `tp:` line. The unit and integration tests of quotes (AA-972..975, AA-1030 tiers) pass unchanged.
- **Which party, which day.** A row is priced for the band's smallest party (all adults, the default room mix: doubles
  plus a single when odd, i.e. twin share) on the window's first bookable day (the window start, or today when it has
  started). The cost sheet cuts windows where a rate changes, so every day of a window prices the same; the smallest
  party is the highest per-person price of the band, the same convention as the cost sheet. `price` = the line for
  that party; `price_per_person` = it / party rounded up like a line. Basis label `per_person_band_min_twin_share`.
- **Discount on the day of the read.** The partner's terms (plan card > catalogue card > tier) are those in force
  today, as a quote made today; a card or tier change applies to the next read. Each row carries the discount (and,
  for staff, the rate card id).
- **RRP shown as stored.** The row's `rrp_amount` (public suggested retail price, ADR 0019 b15) in the row's currency,
  not converted: it is public, and converting would add a second FX rule. The matrix is USD (b16), so with the default
  `currency=USD` both match.
- **One row per window x band.** A window and band held in several currencies is listed once (the USD row first): the
  quote currency is the reader's choice (`?currency=`, any quote currency incl. VND), not the row's.
- **Rows a quote cannot price** (no components, no rate in force for that party, an FX rate missing for a cost
  currency, a plan over the quote's rate-lookup budget) are left out of the agency's tariff and listed for staff
  (`unpriced` + reason). A missing FX rate for a cost currency only unprices those rows (`require_all=False`); a
  missing b2b rule or quote-currency rate is 503, as for quotes.
- **Served tours only**: sellable plans whose tour is in `catalog.v_tour` and not retired / paused
  (`liveness.states(strict=True)`), the set `GET /products` offers; catalog unreadable = 503.
- **Bounded work.** Cells are priced in chunks within the quote's `MAX_RATE_LOOKUPS` (one `price_lines` call, five
  queries, per chunk); a failing chunk falls back to one call per cell to name the failing rows. At most 3,000 matrix
  rows per read (`truncated`), `?source_id=` for one tour.
- **CSV.** One file shape for staff and agency (`tariff.CSV_COLUMNS`), so staff can send the agency exactly what it
  would download; text cells starting with `= + - @` are prefixed with `'` (spreadsheet formula injection). File name
  `aa-tariff-<agency slug>-<currency>-<date>.csv`.
- **Contract minor 1.3.** `GET /booking/b2b/v1/tariff` (scope `read`, the calling partner only: `ctx.partner_id`),
  JSON `Tariff` / `TariffItem` or `?format=csv`. Additive. Root PR `docs/aa1030-g3-tariff-contract`. The guard test
  `test_b2b_responses_never_carry_net_cost_or_margin` walks the new schemas (no net, cost or margin key).
- **Printable page.** Staff page `/pricing/agency-tiers/tariff?partner=<id>` (Agencies tab → "View tariff"): currency
  select, Download CSV (the server CSV through the BFF), Print (`window.print()`). A print stylesheet in
  `app/globals.css` hides the shell (sidebar, topbar, bottom nav) and anything marked `bk-no-print` for every staff
  page. The BFF now passes `content-disposition` through so the browser gets the server's file name.

## Tradeoffs

- Pricing every row through the quote engine costs a few queries per chunk instead of one matrix read; it is the
  only way the tariff equals the quote. A large catalogue (hundreds of plans x 12 rows) is still a handful of chunks.
- The tariff is indicative: a quote is the binding price (FX, rates and discounts move). The page and the contract say
  so; no validity date is promised.
- CRM (AA-Partner) download button: **not built in this lane.** The CRM's Booking client is JSON-only and the CRM has
  no rule yet for which agency roles may see AA's agency prices; a route + web button + role decision + the 90 %
  coverage gate is a slice of its own. The agency can already get the file through `booking.b2b.v1` (1.3). Follow-up.
