# AA-1128 B5: the Booking staff admin in English and Vietnamese

Source: the B5 row of the S283 UI audit (root `docs/audits/2026-11-17-S283-fe-audit/README.md` section 6). Before this
slice about 6 of the 42 staff pages used the kit i18n; the rest showed English only. The same-day tie-break and the
scheduled-drop banner (B0) are a separate PR with their own notes (`AA-1128-b0.md`).

## Decisions

- **One language switch for the whole staff app.** `AdminShell` renders the ONE kit `I18nProvider` (store
  `ui/local/lang.ts`, cookie `bk_lang`), the Topbar carries the kit `LangSwitch` (EN | VI) left of the theme switch;
  below 480 px it hides and Settings › Appearance keeps it. English is the default: no cookie means English.
- **Server and browser agree on the first render.** The staff layout reads the cookie and passes `initialLang`, so a
  Vietnamese user gets Vietnamese HTML from the server (no English flash, no hydration mismatch).
- **Kit catalogues, keyed by the English text.** Each file that shows text has a `<File>.messages.ts` next to it
  (`defineMessages(en, vi)` from `ui/core/i18n.ts`, read with `useT`). The pages that already had a `messages.ts`
  (pricing rules, policy, seasons, holiday events, workbench; S280) keep it.
- **Phrasebook for module-level text** (`ui/local/phrasebook.ts`, `useTx`, `<Phrase>`): status metas, nav entries,
  column definitions and import-free helpers keep their English text at module level; the component that renders it
  calls `tx(label)`. Every catalogue registers itself; a function message is matched as a pattern only when each filled
  part is a number, an amount, an ISO day or currency codes, so data (tour titles, names) is never rewritten.
- **One static registry** (`ui/local/phrases/index.ts` + one file per page group: `shell.ts`, `cases.ts`,
  `supply.ts`), imported once by the shell, so the server holds the same catalogues as the browser whatever pages it
  rendered before. `ui/booking/phrasebookRegistry.test.mjs` checks every catalogue is listed exactly once.
- **Three PRs by page group**, each group with its own registry file so they never edit the same lines:
  1. shell, shared parts (DataTable, FormDrawer, PageState, StatusBadge, ...), dashboard, notifications, pricing,
     staff, settings, audit log;
  2. trip cases, proposals, B2B desk, departures, trip checks, agency billing;
  3. catalog (countries, destinations, trip plans), suppliers and rate sheets, hotels, services, costs and profit
     (finance), supplier bills.
- **Vietnamese wording**: one spelling (huỷ, xoá), "Chờ duyệt / Đang áp dụng / Đã lên lịch" for the maker-checker
  states as on the pricing pages, numbers and dates through the kit `useFormat` (vi-VN separators, dd/mm/yyyy).
- **Formats follow the UI language everywhere (review fix)**: the Booking helpers in `ui/booking/dates.ts`
  (`formatDay`, `localizeIsoDates`, and the new `formatMonth`, `formatLongDay`, `formatNumber`) take the UI language as
  their last argument (English by default, the kit locales en-GB / vi-VN), and `useBookingFormat()`
  (`ui/local/useBookingFormat.ts`) binds them, plus the kit `formatMoney`, to the current language. A component writes
  `const { formatDay, formatMoney } = useBookingFormat();`, which shadows the plain helpers, so a call site keeps its
  shape. Module-level helpers that cannot call a hook (`amountText`, the FX `rate`, `inquiryPrefs`) take `lang`.
- **Labels inside templates are translated first (review fix)**: a module-level English label passed as a template
  argument goes through `tx()` (or the catalogue's own `t()`) before it is placed in a Vietnamese sentence, so no
  title, toast or KPI hint reads "Chuyển sang Discovery" or "Chủ đề: Light".
- **Form state and payloads are never translated (review fix)**: `tx()` is for display only. A stored value (a
  proposal item title, a terms clause) is put into an edit form exactly as stored, so saving a form never writes the
  Vietnamese display text back into data.

## Changed

- The workbench "Provisional: no supplier price yet" pill now holds only "Provisional"; the reason is a muted line
  under it. The pill never wraps, and the Vietnamese text ("Giá tạm: chưa có giá nhà cung cấp") pushed a phone card
  11 px sideways (visual check at 390 px, `VISUAL_LANG=vi`). For the same reason the Vietnamese "Not in the catalog
  now" step reads "Không còn trong danh mục" (shorter than "Hiện không có trong danh mục", same meaning).
- `e2e/visual/session.ts`: `VISUAL_LANG=vi` also sets the `bk_lang` cookie, so the same visual run checks every page in
  Vietnamese (console errors, overflow from longer text, unnamed controls).

## Tradeoffs

- Data stays as entered (tour titles, supplier names, notes, CIS text): only UI text is translated.
- Server-side error messages from the API are matched by code where the page already did so; free-text API errors
  show as the API sends them (English).
- The phrasebook costs one map lookup per rendered label; the pattern check runs only when the exact match misses and
  the template's longest literal piece is in the text.

## Should know

- Guard `ui/booking/uiLocale.test.mjs`: no file under app/, ui/ or lib/ names "en-GB" / "en-US" or calls a bare
  `toLocaleString()`, except the files that map a UI language to its locale. Its `PENDING` list holds the page-group
  files PR 2 fixes; PR 2 empties it (the test also fails when a listed file no longer needs it).

- PRs 2 and 3 are built on PR 1 (they need the shell switch, `useTx` and the shared parts). Ship PR 1 first; 2 and 3
  are independent of each other.
- `ui/core/**` is not edited (kit canonical is AA-CIS-App, ADR 0016); everything Booking-specific lives in `ui/local`
  and `ui/booking`.
- To check a page in Vietnamese locally: `VISUAL_LANG=vi npx playwright test --project=visual-390 -g <slug>` after a
  build.
