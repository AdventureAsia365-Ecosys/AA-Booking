# AA-994 S4b — Booking frontend catch-up to the UI kit core

Root ADR 0016 (one design system, guarded byte copies; canonical AA-CIS-App `frontend/app/_kit/core`), plan row S4b
(`AA-Ecosys/docs/audits/2026-10-27-S252-aa994-design-system/plan.md`).

## Decisions

- **Three layers under `frontend/ui/`.** `core/` = the kit core byte copy (kit-sync from CIS main `fc224ff6`, CIS #1137
  S4a), `local/` = the Booking staff shell (AdminShell, Sidebar, Topbar, BottomNav, CommandPalette, StaffContext, nav,
  signOut, `shell.css`, theme store + hooks), `booking/` = Booking components and pure helpers. `local/` follows the
  Partner `_kit/local/` shape; the shell keeps the CIS inline-style idiom and is out of the kit lint scope.
- **Deleted copies:** `ui/tokens.css`, `tokens.ts`, `brand.ts`, `primitives.tsx`, `Modal.tsx`, `Drawer.tsx`,
  `Toast.tsx`, `DataTable.tsx`, `csv.ts`, `savedViews.ts`, `Providers.tsx`, `sidebarStore.ts`, `useMediaQuery.ts`,
  `useSidebar.ts`; and the Booking components S4a upstreamed: `booking/Section`, `KpiTile`, `FilterBar`,
  `ConfirmDialog`, `RowMenu`, `Money`, `DateText`, and the date half of `booking/DateField.tsx` (the file is now
  `booking/TimeField.tsx`, time field only, until the kit form controls in S6a).
- **Barrel aliases** (`ui/index.ts`): `Section`, `KpiTile`, `FilterBar` (+ `FilterField`, `useUrlFilters`,
  `FilterSelect`), `RowMenu`, `DateField`, `Money`, `formatMoney`, `minorUnits`, `DateText`, `relativeTime` are the core
  exports; `ConfirmDialog` = core `ConfirmModal` (accepts `message` / `danger`). Pages kept their props; the deep
  imports `@/ui/booking/DateField`, `@/ui/booking/RowMenu`, `@/ui/primitives`, `@/ui/brand`, `@/ui/signOut`,
  `@/ui/theme` moved to `@/ui`. The two server layouts import their modules directly (`@/ui/core/Toast`,
  `@/ui/core/brand`, `@/ui/local/theme`, `@/ui/local/AdminShell`, `@/ui/local/StaffContext`), not the mixed barrel.
- **`PageFrame` is a thin wrapper, not a bare alias**: core defaults are `width="full"` and padding 28/36/56 px; the
  Booking wrapper passes `width="wide"` (1440 px column) and `padding: 24px 32px` (the former `px-8 py-6`), so pages
  do not move. The phone rule (`ui/local/shell.css`) and the 768–1199 px compact rule keep overriding the gutter via
  `.aa-admin-main … !important`.
- **Theme:** `ui/local/theme.ts` = `createThemeStore({ storageKey: "bk_theme" })`, hooks via `createThemeHooks`; the
  root layout uses `themeStore.restoreScript` (same script semantics as before).
- **Sidebar key:** the core `sidebarStore.ts` has a fixed key `cis_sidebar` (not configurable). Booking now uses it;
  the restore script in `app/layout.tsx` copies a stored `bk_sidebar` choice to `cis_sidebar` once and removes it, so
  a collapsed rail stays collapsed. localStorage is per origin, so the key never meets the CIS admin's.
- **Toolbar filters:** the Booking DataTable wrapper puts a page's FilterBar in the toolbar; the CSS that turns the bar
  root into `display: contents` now targets the core class `.aa-kit-filterbar` with `!important` (the core root's
  block layout is an inline style). Same effect as the core `layout="toolbar"`, without a per-page prop.
- **Kit lint:** `eslint.config.mjs` uses `kitConfig({ preset: "tailwind" })` on `app/**` and `ui/booking/**` at
  error (in `ui/booking/**` `no-hand-styled-button` is off: plan G5 applies outside `ui/**`). It replaces the three
  AA-683 `no-restricted-syntax` rules. The `react-hooks/incompatible-library` exemption names `ui/core/DataTable.tsx`
  only. Baseline: `eslint-suppressions.json`, 99 violations in 45 files (69 `no-hand-styled-button`, 26
  `no-raw-main`, 4 `no-hex-colour` in Tailwind arbitrary shadows). Two `accent-[var(--aa-accent)]` checkboxes became
  `accent-accent` (same colour, no suppression needed).
- **CI (Frontend Build):** before `npm ci`: integrity (`check-kit-copy.mjs`), `--css .` (no `--aa-*` outside the core
  tokens), provenance (`backend/scripts/check_kit_provenance.py`, copied from AA-Partner with only the docstring
  changed, plus its unit test with Booking paths). After `npm ci`: `eslint --max-warnings 0 --prune-suppressions`,
  "suppressions file is pruned", "suppressions do not grow" (vs the base branch file), "no inline disable of a kit
  rule" for `app` and `ui/booking`. The pre-push hook runs integrity + `--css` with the lint.
- **Next 16.4.1 → 16.4.2** (plan row). Lockfile regenerated with npm 11 (`npx npm@11 install --package-lock-only`):
  the local npm 10 drops the `libc` fields of the optional platform packages.

## Changed (vs the plan row)

- `shell.css`: the AA-679 `:root:has(.aa-bottom-nav) { --aa-modal-inset-bottom: 76px }` rule is removed (an `--aa-*`
  definition outside the core, and the core Modal does not read the variable). Added `.aa-page-header-text` /
  `.aa-page-header-actions` (the core PageHeader moved its flex values into classes that CIS defines in its
  `globals.css`); the CIS phone "stack" rule is left out to keep the Booking headers as they were.
- `app/globals.css` keeps three Booking measurements the core parts changed (found by the pixel comparison below):
  the KpiTile hint line height (`[data-kit-kpi] > div:nth-child(3)`: Tailwind's `--text-xs--line-height`, 2 px per
  tile), and the ConfirmDialog message and reason box line height (`[data-testid="confirm-dialog"]`, 20 px instead of
  21 px). Both are plain CSS on unstyled properties (no `!important`); upstreaming them into the core would change the
  CIS tiles and dialogs, so they stay Booking-local.
- e2e layout spec: test ids follow the core FilterBar (`kit-filterbar`, `kit-filterbar-reset`, `data-kit-filter-row`).

## Tradeoffs

- Kept `ui/booking/dates.ts` whole (it also has `formatDay` / `isIsoDay` / `parseDayInput`, now duplicated in
  `ui/core/format.ts`): it is import-free on purpose for the node:test suite and holds the time helpers TimeField needs.
  Drop the duplicates when TimeField moves to the core (S6a).
- A wrapper for PageFrame instead of changing 40+ pages to pass `width` / `style`: one place, no visual drift.

    fonts): nothing in Booking read them before.
  - Core fixes that come with the copy: Drawer title wraps instead of pushing the close button off-screen, DataTable
    phone skeleton is card-shaped, `aria-sort` on sorted headers, Toast z-index 10001.
- **Not carried over (follow-ups for the CIS core):**
  - AA-679 Modal layout: the Booking copy kept header + footer fixed and scrolled only the body, fitted the overlay
    (max-height 100%) and ended above the phone bottom nav. The core Modal scrolls the whole dialog (max-height 90vh)
    over the bottom nav. Affects only dialogs taller than the screen on a phone; upstream the layout to the core
    Modal (CIS), then sync.
  - The DataTable page-size select lost its `aria-label="Rows per page"` (Booking local deviation, S236 finding 11);
    the previous / next buttons keep theirs (core). Upstream the label.
- Local checks: tsc, lint (with suppressions), 41 unit tests, `next build`, integrity / `--css` / provenance, and the
  full `layout-mock` Playwright suite (275 tests) are green.
- Pixel comparison: the 200 `layout-mock` screenshots of `origin/main` (b2a2124) and of this branch (same mocks,
  1440 / 1400 / 1280 / 1100 / 960 / 390 px, light and dark) were diffed. No page moves: a vertical-offset search finds
  0 px shift on every shot except the two confirm-dialog shots (1 px at 1440; 6 px at 390, where the dialog is now
  centred in the full screen instead of above the bottom nav: the AA-679 item below). The remaining pixel differences
  are the token colours listed above (muted / muted2 text, gold-button labels, accent-deep, green, amber, dark info)
  and anti-aliasing.
