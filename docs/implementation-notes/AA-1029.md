# AA-1029 R4: tour price chain (S267, lane r4-price-chain)

## Decisions

- **Scope per ADR 0019** (S265 re-scope comment on the issue): only `b2b` and `fixed_departure` are computed; the
  "from" price is the suggested retail price (RRP = the agency price + `rrp_markup_pct` of the b2b rule, b15). Agency
  tier discounts (0 / 3 / 6 %) are AA-1030, not here.
- **RRP stored on the row** (`trip_plan_prices.rrp_amount`), not computed in the view: the view stays a plain read
  (no rule join for TripPlanner), the history keeps the RRP as it was, and a markup change is a recompute input.
- **Bridge creates plans not sellable.** Every catalog key gets a plan so prices can flow, but selling stays a staff
  decision (B2B products list sellable plans only). The from price does **not** require `sellable`: an indicative
  "from" price is shown for a priced tour, bookable or not.
- **Bridge reads `catalog.v_tour`** (existing contract catalog.tour.v1) for keys. The CIS source price text needs a
  new CIS view (`catalog.v_tour_price_reference_v1`, CIS 365); Booking feature-detects it, so the bridge works before
  that migration and the reference part answers `skipped`.
- **Cost sheet band party = the band's smallest party** (fixed costs shared by fewer people: the price covers the
  whole band). Room mix = doubles + a single when odd (singles only on a one-person room type).
- **Rate choice = the B2B quote's** (`rates_in_force_many`), so a quote of the plan and its matrix agree.
- **Windows** cut at every rate validity edge shifted by the component's day offset, merged when nets, season and
  peak match, **anchored on the rate validity, not on today** (review fix): the first window starts where its rates
  start (it may lie in the past), windows already over are left out, and the last one ends with the latest rate
  (`9999-12-31` when open-ended; no 365-day cap, `MAX_SEGMENTS` = 60 bounds the work). Earlier the windows started
  today and the horizon was today + 365, so every daily run rewrote the matrix, the history and `updated_at`. `peak` when a used rate's season label contains
  "peak" (the rule's uplift then applies).
- **Mixed currencies**: one rate currency keeps it (an FX change then re-prices); mixed = summed in USD at the plain
  approved rate. Selling currency USD (b16).
- **Recompute trigger**: a watermark hook (approvals, contracts, rates, plans, component count, UTC day) instead of
  hooks in every write path: one place, works for SQL loads (DB Migrate run-script) too. Plus `POST …/recompute`.
- **Hand rows win**: not computed, or computed + overridden. A computed row overlapping one is left out, except a
  hand row already over (`valid_to` before the recompute day): the computed row then starts the day after it
  (`trimmed`), since anchored windows can start in the past and an old hand row must not hide today's price.
- **Plans recomputed**: every plan with a component, a computed row **or a b2b row** (review fix): a plan priced by
  hand gets its RRP filled (rows from before bk-039) and refreshed when a new markup is approved.
- **History**: one row per price row per change, closed by `effective_to` (column grant only). FK `ON DELETE CASCADE`
  (role booking cannot delete plans; tests and the owner can).
- **Rate sheet import** matches existing items only (hotels by code + room type name, services by code); supply facts
  stay the admin's (ADR 0004a). Upload as base64 JSON because the BFF forwards JSON only (same as photos).
- **ApiError keeps the whole body** (frontend) so the drawer can list the rate-sheet problems.

## Changed

- `FROM_PRICE_SQL` (staff list, detail, matrix) and price parity now read the b2b RRP (B2C rows no longer count).
  Parity falls back to the bk-009 price hint when no RRP row exists.
- `rates_in_force_many` returns the rate's `season` too.
- New rows in the matrix editor default to `b2b` (B2C retired).

## Tradeoffs

- The UTC day stays in the watermark (a rule or FX rate dated to start today, a window that ended); with anchored
  windows an unchanged day finds nothing new and writes nothing.
- The watermark can run one extra recompute after its own write (the plan's `updated_at` moves): it finds nothing
  new and writes nothing (an order-insensitive compare).
- A sync of ~1,000 keys every 15 minutes is one `INSERT … ON CONFLICT` and one `UPDATE` with `synced_at IS NULL`:
  cheap, and plans are never deleted.
- Rate sheets with errors write nothing (all or nothing) rather than importing the good rows: easier to reason about
  and to fix in the workbook.

- Review finding "drop `fixed_departure`, Booking is B2B only" was not applied: the tech lead's approved re-scope on
  the issue (S265 plan review) and the R4 milestone ("booking channel CHECK allows only b2b and fixed_departure") keep
  `fixed_departure` as a priced channel (fixed departures sold to agencies). ADR 0005's "B2C" label on that row
  predates ADR 0019; if the tech lead wants it gone, it is the one-line `CHANNELS` change plus its test.
