# AA-952 — Hold answers carry the held quote (booking.b2b.v1 1.2)

Card: root `docs/audits/2026-10-21-S246-crm-design-v3/design-v3.md` CRM-23 (Module 7) and milestone C-M3 ("confirmed"
step). The AA-Partner side of this slice (AA lines from the accepted hold set, confirm after the deposit) is in
AA-Partner `docs/implementation-notes/AA-952.md`. Session S259, agent Claude Code.

## Decisions

- **No new confirm endpoint**: `POST /holds/{id}/confirm` exists (AA-973) and is idempotent on the hold (a confirmed
  hold returns its booking whatever key the retry carries); it confirms every line of a multi-line hold set and
  answers each `line_ref`. The CRM needed only what it cannot keep itself: the held quote's `price_hash` (the confirm
  presents it) and each line's `b2b_price` with the quote's FX lock (the agency's AA line net).
- **Additive fields on `Hold`** (place, read, extend answers): `price_hash`, `currency`, `fx` (same shape and selling
  rate as `POST /quotes`), `lines[].b2b_price`. Optional in the response model (left out only when the quote row cannot
  be read), so oasdiff sees no breaking change and a 1.1 reader ignores them.
- **No migration**: `booking.b2b_quotes` / `booking.b2b_quote_lines` already store the hash, FX lock and line price.

- `backend/app/routers/b2b.py`: `HoldLine.b2b_price`, `Hold.price_hash` / `currency` / `fx` (optional).
- `docs/api/openapi.json` regenerated (`scripts/export_openapi.py`).
- Tests: `tests/unit/test_b2b_hold_flow.py` (2 new), `tests/integration/test_bk020_b2b.py` (GET hold carries the

- `CONTEXT.md` B2B API "Holds": contract 1.2.

## Tradeoffs

- A `GET /quotes/{id}` route was the other option; folding the quote into the hold answer keeps one call for the CRM
  (it reads the hold anyway to learn its status) and exposes nothing the `POST /quotes` answer did not already give
  the same partner.
