## Decisions

- **Key bk-076, file `migrations/076_aa1037_retire_b2c.sql`.** `main` ends at `075_season_sync_checks.sql`; bk-045
  went to the finance file (AA-1074) and bk-046..075 to later work, so the drop takes main max + 1. The name keeps
  `aa1037_retire_b2c` so it still matches the root DRY RUN draft (`docs/audits/2026-11-05-S270-aa1037-b2c-drop-dryrun/
  migrations/bk_NNN_aa1037_retire_b2c.sql`) and its script. Every self reference (header, RAISE texts, comments,
  `archived_by`, the registration row) says bk-076. The Infra copy is byte-identical at
  `db/migrations/booking/076_aa1037_retire_b2c.sql`.
- **Body unchanged apart from the key.** Kept as they were: the 30-day freeze guard (last-write block byte-equal to
  the DRY RUN's `LAST_WRITE_SQL`), the `pins` placeholder with every value null (a database that holds a B2C row
  refuses "has no DRY RUN pin" until the pins are pasted), the owner guard (`bk_owner`), the no-intake-job guard, the
  no-outside-dependants guard and the `SHARE ROW EXCLUSIVE` lock from the first statement to the drops.
- **`000204c8` not cherry-picked.** Its integration-test changes (the `b2c_guard_off` fixture, the b2c case helpers on
  either side of the drop, the retired B2C routes in the API tests) reached `main` with the R4b code PR (#199). A
  no-commit cherry-pick left an empty diff once the four conflicts (all `main` evolutions: `make_sellable`,
  `activate_supplier`, `read_sample(pool, 2.0)`) were resolved to `main`'s side.
- **Test re-run rule renamed.** `conftest.SUPERSEDED_BY_BK076` (still `range(1, 37)`) and `BK076 = 76`: a re-run of the
  suite skips bk-001..036 once bk-076 is registered. Keyed on bk-045 it would have skipped them on every run, because
  the finance file registers bk-045. The schema-guarded skips in `test_bk014_owner`, `test_bk018_pii_tags`,
  `test_bk020_schema`, `test_bk025_ops_views` and `test_bk030_schema` read `bk-076` for the same reason.
- **No code PR and no readiness raise.** This build reads none of the dropped objects (R4b) and runs on either side of
  the drop; `REQUIRED_SCHEMA_VERSIONS` stays as it is (the preflight notes bk-076 is "not required by readiness").

## Tradeoffs

- Kept the issue id of the S270 draft in the file name (`aa1037_`) for the DRY RUN trail rather than a plain name like
  the newer files; the preflight's dangling-reference check is satisfied either way.
- `ops_files_guard` (bk-030 body, kept) still answers "supplier booking does not exist" for a departure-level supplier
  booking (bk-045 finance made `supplier_bookings.trip_case_id` nullable) because it joins `trip_cases`. That is
  `main`'s behaviour today, not something the drop adds; changing it here would mix a fix into a destructive file.

  allowlist has no stale entry", `db/check_rls_allowlist.py`) goes red until both copies lose it. Two draft PRs are

  `chore/aa1061-rls-allowlist-copy` (`db/rls_catalogue_rules.py`, the same bytes). Order: DB Migrate apply of bk-076
  succeeds, then the CIS PR merges, then the Infra PR (its Copy Guard compares the copy with CIS `main`), both before
  the next 02:17 UTC run. They do not merge before the apply: until then the entry still matches the live grant, and
  the nightly Dev reference would show that grant as a rule-g violation for every day the apply waits for its pins.
