# AA-1030 — Agency price tiers (Booking side)

Lane l9 of S269. Linear AA-1030, re-scoped on 03/11 (S265 plan review) under root ADR 0019 b15: one net price per
tour per season, three agency tiers with percentage discounts set per contract (0 / 3 / 6 % to start), RRP = net +
25 % (AA-1029), values are policy data editable in Booking admin with maker-checker. The CRM half (agency retail
markup) is in AA-Partner `docs/implementation-notes/AA-1030.md`.

## Decisions

- **What the discount is taken off.** "Net" in b15 is the agency (b2b) price Booking quotes: the b2b rule's price of
  the plan / component (net cost / (1 − margin − card fee)). The tier discount is taken off that b2b price, line by
  line, before the line is rounded up. The RRP (net + 25 %) and the public "from" price (`price.from.v1`,
  `/price-parity`) stay the same for every agency: the RRP is the public suggested price, the discount is the
  agency's extra margin. (The orchestrator brief said "discounts off RRP"; a 0 % Standard tier off the RRP would leave
  the agency no margin, so the brief was read as "off the agency price the RRP is built on", as the master plan
  slot says: "giảm 0/3/6 % trên net".)
- **Discount, not margin per tier.** The Linear text asked for "a margin rule per tier"; the S265 re-scope and b15
  replaced it with a discount per tier. One `b2b` pricing rule stays; tiers only discount it.
- **Storage (bk-045).** `partner_tiers` (code + label, seeded standard / silver / gold), `partner_tier_discounts`
  (dated, append-only, approved rows; seeded 0 / 0.03 / 0.06 from 2026-11-01, approved as `seed:bk-045`),
  `partner_rate_cards` (per partner, whole catalogue or one trip plan, `valid_from` / `valid_to`, approved),
  `partner_price_approvals` (the approvals of both, maker-checker trigger), `b2b_partners.tier_code` (default
  `standard`), quote columns (`b2b_quotes.partner_tier_code` / `tier_discount_pct`, `b2b_quote_lines.
  agency_discount_pct` / `rate_card_id`).
- **Own approvals table.** Not more entity types on `booking.policy_approvals`: bk-007 and bk-021 re-add that table's
  entity CHECK when the integration tests replay every file, and the new approval rows would then fail it.
- **Precedence.** A plan rate card in force > a catalogue rate card in force > the tier's approved discount > 0 %.
  A 0 % card still overrides the tier (a contract can say "no discount on this tour").
- **Ending a card (review fix, S269).** Cards are append-only and a newer card with a `valid_to` only covers an older
  open-ended card for a while, so without an end a card approved by mistake or a terminated contract could never go
  back to the tier. Chosen: an **end card** = a `partner_rate_cards` row with `discount_pct` NULL (bk-045 CHECK allows
  NULL), same maker-checker. `CARDS_IN_FORCE_SQL` still picks the newest approved card per scope; `discount_for()`
  skips an end card (plan scope falls back to the catalogue card, then the tier). The scope-day unique index includes
  `(discount_pct IS NULL)` and the order puts an end card first on one day, so a card can be ended from its own first
  day. Rejected: a separate `partner_rate_card_ends` table (one more table, approval entity and retention row for the
  same effect). UI: the Rate cards tab has an "End" button on in-force / scheduled cards that opens the drawer as an
  end card; the API takes `discount_pct: null` (required field, null = end).
- **Tier assignment** is `pricing.write`, audited (`b2b_partner.tier_changed`), with no second person: it changes no
  rate (the rates themselves are maker-checker). Projected partners (bk_tenant_pull) keep their tier: the pull never
  writes `tier_code`.
- **Hash.** A line with a discount adds `agency_discount` + `rate_card_id` to the `price_hash` payload; a 0 % line
  hashes exactly as before (no hash version bump), so every existing Standard quote keeps its hash.
- **Floor: warn, never block.** With the seeded b2b rule (15 % target, 10 % floor, 3 % card fee) Gold's 6 % leaves
  about 9.8 % margin, under the floor. Nothing is capped (the discount is the contract's; capping would silently
  break it); the Agency tiers page shows the margin left per tier under the rule in force and flags it. The business
  owner question 2 below asks which way to go.
- **Contract `booking.b2b.v1` unchanged.** The quote body has no new field (the discounted price is just the
  `b2b_price`). `price.from.v1` stays the public RRP; the contract says per-tenant prices are a later version, so no
  per-agency "from" was added to `/price-parity` (the CRM suggests its retail price from the quote's b2b price and the
  RRP, see the AA-Partner notes).

## Tradeoffs

- Rate cards are a discount, not a fixed contract price list per tour × season × pax band. A fixed price list would
  need its own matrix and sync with the cost sheet; a discount per tour covers "special contracted rates" with one
  number and stays correct when supplier rates change. A fixed list can be added later as a new card kind.
- Two migrations PRs would have been cleaner per table; one contract file keeps the wave's Booking batch to one
  Migration Apply.

## Live check (Dev, after deploy)

Script: root `.tmp-session/S269/live/aa1030_tiers_live.py` (runs in the `aa-booking-dev-api` container through the
S3-mediated ECS exec runner, role `booking`, $0). It projects nothing new: it reuses two invented partner rows (created
once, fixed tenant ids, suspended at the end so nothing can call the B2B API as them), puts them on silver and gold
through `set_partner_tier` (audited as the Dev E2E staff row), quotes the same tour for both through
`quotes.create_quote`, then adds a catalogue card for the gold one (maker and checker are script labels), quotes again,
ends the card with an approved end card and quotes a third time (back to the gold price). It prints one JSON line
with every price, the tier discount and each line's `agency_discount_pct` / `rate_card_id`. The CRM half is
`.tmp-session/S269/live/aa1030_crm_markup_live.py` (AA-Partner notes).

## Questions for the business owner (session-end Jira draft)

The mechanism is built with the ADR 0019 b15 starting values; each answer is a data change in Booking admin, no code.

1. **Tier levels.** Keep three tiers (Standard 0 %, Silver 3 %, Gold 6 %)? What moves an agency up a tier (yearly
   volume, number of bookings, contract signature)?
2. **Gold and the margin floor.** The B2B margin rule is 15 % with a 10 % floor (3 % card fee). Gold's 6 % leaves AA
   about 9.8 %, under the floor. Options: (a) accept it for Gold, (b) lower Gold to 5 %, (c) raise the B2B margin
   (for example 17 %) so every tier stays above 10 %. Proposed: (c) or (b), the tech lead's preference is (b) until the
   first contracts are signed.
3. **Margins per channel.** B2B margin 15 % and RRP = agency price + 25 % for every product type (tours, hotels,
   transfers)? Or a different RRP markup for stand-alone hotel nights and transfers?
4. **Contract rate cards.** Are special contract rates a percentage off our agency price (built), or fixed prices per
   tour and season (later)?
5. **Agency default retail markup (CRM).** If an agency sets no markup of its own, the CRM suggests the RRP for tours.
   For hotels and transfers sold alone there is no RRP: suggest nothing, or suggest our agency price + 25 %?
