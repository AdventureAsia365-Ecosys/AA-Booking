# AA-902: no AWS account IDs or ARNs in this public repo

## Decisions

- **The archive bucket name is built at run time.** `app.retention.policy` keeps only the stem `aa-cis-bronze`;
  `app.retention.jobs.default_bucket()` reads the account from STS `GetCallerIdentity` (needs no IAM permission) and
  returns `aa-cis-bronze-<account>`. It is `functools.cache`d (one STS call per process) and only called when a live
  run has rows to archive. No new environment variable and no Infra change: the task already reaches STS like every
  other AWS API it calls.
- **Results and the summary show `aa-cis-bronze-<acc2>`** (`ARCHIVE_BUCKET_DISPLAY`) instead of the real bucket.
  They are display strings in `booking.job.result` / the admin API; object keys are unchanged.
- **The Cognito WORKFORCE issuer stays a code default** in `backend/app/auth/identity_config.py` and
  `frontend/lib/cognito.ts`, marked `docs-lint: ignore`. The pool ID is public by design (every token's `iss`, the
  JWKS URL, the browser redirect), and both already accept an env override. Docs no longer repeat it.
- **Blocking check:** `.github/scripts/check_resource_ids.py` (stdlib), run as the first step of the required
  `Security Audit` job, so a finding blocks the merge without adding a new required check. It scans every tracked
  text file with the AA-Ecosys docs-lint resource-ID patterns, plus a 12-digit number after `-` (bucket names).
- **Allowlist:** `123456789012`, one repeated digit (`111111111111`), the last group of a UUID, a user-pool ID that
  says TEST/EXAMPLE, and lines carrying `docs-lint: ignore`.

## Changed

- `backend/app/retention/{policy,archive,jobs}.py`: `ARCHIVE_BUCKET` constant removed; `archive_bucket()`,
  `default_bucket()`, `bucket_factory` parameter on `run_spec` / `build_handlers`; `S3Archiver` takes the bucket.
- Tests: unit tests for `archive_bucket` / `default_bucket` (stubbed STS); the integration test passes a test bucket
  and asserts every `put_object` goes to it.
- Docs: `CONTEXT.md`, `docs/implementation-notes/AA-825.md` (`<acc2>`), `AA-683.md` (`<api-id>` for the old
  execute-api host).
- CI: `.github/workflows/ci.yml` Security Audit step; `.github/scripts/check_resource_ids.py`.

## Tradeoffs

- STS vs an env var: an env var needs a task-definition change in AA-CIS-Infra and a value someone has to keep
  right; STS always answers with the account the task really runs in. Cost: one extra API call per process on the
  first live archive, and a live run fails (before deleting anything) if STS is unreachable.
- Scanning every tracked file (not only docs) catches workflow and code literals, the actual leak; the price is a
  rare false positive, handled with the allowlist or the ignore marker.
