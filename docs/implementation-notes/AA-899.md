# AA-899 — OpenAPI export and breaking-change check (AA-Booking part)

Issue scope: CI exports `openapi.json` for CIS and Booking, oasdiff on PRs against `main`, `response_model` for public
routes, publish the spec with the release. Done when: a test PR removing a public field fails unless labelled
breaking. Same design as the AA-CIS-App half (`AA-CIS-App/docs/implementation-notes/AA-899.md`, which holds the
shared reasoning in more detail).

## Decisions

- **Committed `docs/api/openapi.json` + two checks.** The required Unit Tests check fails when the file is stale
  (`backend/tests/unit/test_openapi_export.py`); the new workflow `api-contract.yml` (job "OpenAPI breaking changes")
  diffs the base tip's committed file (`HEAD^1` of the merge commit) against the PR's with oasdiff 1.33.0 (release URL
  + SHA-256 pin). No Python install in that job.
- **Built from code only:** `create_app(load_settings({"ENVIRONMENT": "test"}))`, no database, no network (verifiers
  fetch keys on first use, the lifespan never runs), no secret. Deterministic: sorted keys, no `servers`,
  `info.version` = `unreleased` (a release PR only bumps the version and must not make the file stale),
  `info.x-generated-by`. Same bytes with PYTHONHASHSEED 0 and 4242. FastAPI and Pydantic were already pinned.
- **Public paths** (`PUBLIC_PATHS: ^/booking/(b2b/|health|ops/)`): the B2B API (AA-Partner, contract
  `booking.b2b.v1`), health (ALB, deploy smoke), `/booking/ops/*` (the Deploy Dev workflow). Breaking changes there
  fail. Staff routes are called only by `frontend/` in this repo, changed in the same PR: warnings only.
- **Severity:** oasdiff ERR, plus `response-optional-property-removed` and `request-parameter-removed` raised to error
  (`.github/oasdiff/severity-levels.txt`). Exit codes other than 0/1 always fail.
- **Escape hatch:** label `api-breaking` or a `type!:` title; the workflow listens to `labeled`/`unlabeled`/`edited`.
- **Response models:** the B2B routes already had strict models; the only untyped public bodies were health.
  `/booking/health` now has `response_model=Health`; `/booking/health/ready` keeps its `JSONResponse` (200/503) and
  documents `Readiness` through `responses=`.
- **Release asset:** `release-please.yml` uploads `aa-booking-openapi-vX.Y.Z.json` (version stamped by `jq`) with the
  CI bot App token after a release is created.
- `.github/scripts/openapi_breaking.sh` is a byte copy of the AA-CIS-App file (same script, path rule passed by env).

## Changed

- New: `backend/scripts/export_openapi.py`, `docs/api/openapi.json`, `docs/api/README.md` (APP-05-booking, draft),
  `backend/tests/unit/test_openapi_export.py`, `.github/workflows/api-contract.yml`,
  `.github/scripts/openapi_breaking.sh`, `.github/oasdiff/severity-levels.txt`.
- `backend/app/routers/health.py`: `Health` and `Readiness` models (bodies unchanged).
- `.github/workflows/release-please.yml`: two steps. `CONTEXT.md`: layout + "API reference" paragraph.

## Tradeoffs

- A full spec in a public repo: derived from the public source only, no host, resource-ID check clean. The live
  `/booking/openapi.json` stays gated (AA-876).
- Staff routes are not gated: skew between a Vercel deploy and an ECS deploy can still break the staff admin for a
  few minutes; the warnings list them in the job summary.

## Should know

- After merge: add "OpenAPI breaking changes" to the required checks, then a canary PR that drops `valid_until` from
  the B2B `Quote` model must fail and pass with the `api-breaking` label. Local proof: oasdiff reports
  `response-required-property-removed` on `POST /booking/b2b/v1/quotes`, exit 1; `ALLOW_BREAKING=true` exit 0.
- A FastAPI/Pydantic bump must regenerate the file in the same PR (`cd backend && python3 scripts/export_openapi.py`).
