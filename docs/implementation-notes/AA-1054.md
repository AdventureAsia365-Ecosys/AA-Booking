# AA-1054 — pilot fence (S297 slice, lane l9-pilot-fence)

Tech lead decision S295 (sec-Q11): disable the Dev-only E2E identities on the pilot day, not at go-live, and add a
shared `is_pilot` fence for CIS and Booking. This slice builds the fence; it removes no E2E exception, allow-list or
bridge code (the E2E suites still need them until the pilot day).

## Decisions

- **One switch, owned by CIS.** The CIS platform setting `cis.platform.pilot_e2e_fence` (CIS 495; bool, default off,
  maker-checker, high impact, no env override, audited by the CIS settings registry). Booking does not keep its own
  pricing policy copy: two switches could disagree on the pilot day.
- **How Booking reads it without a cross-app write grant.** CIS 496 adds the contract view `catalog.v_pilot_fence_v1`
  (one row: `fence_on`, `version`, `effective_from`), SELECT to role `booking` only, like every other catalog view
  Booking reads. Booking has no privilege on `shared.setting_definition` / `shared.setting_value`.
- **Who is fenced.** Any token address of the E2E mailbox domain (`e2e-mail.lumiguides.it.com`), any local part: a new
  or a look-alike E2E address is fenced too, and no list has to be kept in step.
- **Where.** In `current_staff`, right before the first database read. The checks before it need no database and only
  refuse more (Preview cap, read-only E2E admin writes, E2E owner and writer scope), so the many unit tests that assert
  "refused before any DB access" keep their meaning.
- **Fail closed.** View missing, no grant, no row, a non-boolean or a database error: 403 `e2e_pilot_fence_unknown`
  for E2E identities only. Real staff never read the view.

## Changed

- `app/auth/pilot_fence.py` (new), wired in `app/auth/staff.py`.
- Tests: `tests/unit/test_aa1054_pilot_fence.py`, `tests/integration/test_aa1054_pilot_fence.py`; the unit fake
  `ScriptedConn` answers the fence "off" by default and records fence reads in `fence_calls` (not `calls`); the
  integration stub `catalog.v_pilot_fence_v1` (stub_catalog.sql) holds one "off" row.

## Tradeoffs

- 30 s process cache (technical constant, like the admin MFA switch): turning the switch on takes up to about one
  minute end to end (CIS settings cache 30 s + this cache). The runbook waits one minute before the read-back.
- A fence read per E2E request costs one tiny query every 30 s per process; real staff pay nothing.
