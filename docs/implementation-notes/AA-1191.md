# AA-1191 — USD only (Booking part)

Lane l4-usd of S297. The CIS side (the setting, the contract view, the admin pages) is in AA-CIS-App
`docs/implementation-notes/AA-1191.md`.

## Decisions

- **Read path**: `catalog.v_billing_currencies_v1` (CIS 498, contract tenant.entitlements.v1 1.12), SELECT to role
  `booking` only, one row `enabled_currencies text[]` (USD first) + `base_currency`. Feature-detected with
  `liveness.view_ready`: without the view Booking keeps USD only (the setting's default), so this PR is safe before
  CIS 498 is applied. No Booking copy of the value, no Booking setting: CIS owns it.
- **Drafts bill the effective currency**: an agency whose CIS `billing_currency` is not enabled is drafted in USD
  from the USD list; the run counts `currency_not_enabled`. The existing currency-move logic then empties the job
  lines of the period's VND draft (`currency_moved`), exactly as when CIS changes an agency's currency.
- **Refused write**: `PUT /booking/billing-terms/default|agencies/{tenant}` with a `saas_currency` that is not enabled
  is 422 `currency_not_enabled`, unless it is the stored value sent back unchanged (the field is a read-only fallback
  on the page; an unrelated edit must not fail).
- **Page**: `GET /booking/billing-terms` adds `enabled_currencies`; the Settings › Payment terms page hides the
  software fee currency field while only USD is enabled.
- **A save never converts (review fix)**: the first cut showed a stored VND as USD in the form and sent USD back, so a
  deposit-only edit rewrote `booking.billing_terms.saas_currency` VND -> USD (a data conversion this lane must not
  do; the DRY RUN counts exactly those rows). Now the form keeps the stored value and `parseTerms` leaves
  `saas_currency` out of the PUT body (the field is read-only on the page); `BillingTermsIn.saas_currency` defaults
  to None and `put_terms` keeps the stored value when it is missing. A new row sent without it takes the default
  row's currency while that is enabled, else USD, so a new override copied from a VND default is not refused. An
  explicit currency is still checked (refused unless enabled or equal to the stored one).

## Changed

- `app/agency_billing/currencies.py` (new), `drafts.py` (effective currency), `config.py` (refusal), the terms list
  route, the frontend terms section and `lib/billingTermsForm.ts`.
- Tests: `tests/unit/test_aa1191_enabled_currencies.py`; `tests/integration/test_aa1116_saas_draft_pg.py` stands in
  the 498 view (VND enabled for the existing VND cases) and adds the USD-only case.

## Tradeoffs

- Existing VND invoices (issued or draft) stay as they are and still show on Agency invoices: hiding real invoices
  from finance would be wrong. The DRY RUN counts them; voiding or reissuing is a later reviewed step.
- The B2B desk quote currency picker (USD / EUR / VND) and the pricing policy `agency_currency_by_country`
  (`VN=VND`) are agency booking prices, not SaaS invoices; they are left for a follow-up (named in the PR body).

## Should know

- No migration in this repo. Chain: CIS 498 applied first gives the real value; before it the code serves USD only.
