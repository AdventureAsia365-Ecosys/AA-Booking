# AA-1145 — One supply model: pax types, structured contract terms, restrictions and allotment, stop-sale

Lane l13 of S285 (slice L5 of root `docs/audits/2026-11-19-S285-session/advisory-r2-plan.md`). Migration bk-060
(migration-only PR first, MIG-4), then this code PR. The rest of the T13 role matrix is AA-1150.

## Decisions

- **One migration, contract class.** The model needs columns and CHECKs on `supplier_rates` and a config row in
  `pricing_policy` (both contract under ADR 0017), and the guard trigger functions are `CREATE OR REPLACE` (re-runnable
  for the integration replay). Splitting the new tables into an expand file would not ship anything earlier: the code
  needs the columns too.
- **Terms in their own table** (`supplier_contract_terms`, one row per contract) instead of new columns on
  `supplier_contracts`: the bk-008 lock function lists the contract columns one by one, and new columns there would
  need it replaced; a separate table has its own draft-only guard, and an offer (activity slice) can reuse the same
  shape for its override.
- **One restrictions table for rooms and services.** allotment / free_sale / on_request rows are contract terms (status
  `contract`, written under a draft, counted while published); `stop_sale` rows are events on a published contract
  with the season-range CHECK pattern (pending / approved / rejected / withdrawn, end request + end by two people).
- **Stop-sale takes effect while pending** (T13 review 2.4); rejected or withdrawn it stops counting; lifting an
  approved one needs a second person. Applied to the season calendar stop-sale ranges too (`seasons.RANGES_SQL`),
  which is the review's exact code change.
- **Permission `stop_sale.write` = admin + contracting.** Sales 403. Reading = `supply.read`.
- **Engine precedence:** stop_sale > allotment (units left and not released) / free_sale (party within max) >
  on_request. Several allotment rows on one date add their units. Allotment use = requested + confirmed supplier
  bookings (one room per booking and night; a service's pax per day): rooms per booking and the contract a booking
  used come with the hotel slice.
- **Quotes: the engine only lowers availability for now.** A line without a departure stays `on_request` even on a
  free-sale date, because the hold re-check (`departures.lock_departures`) holds every such line on request and the
  desk accepts it; showing `available` in the quote would contradict the hold. The staff check endpoint shows the
  engine's full answer. Turning free-sale / allotment into "confirm at once" belongs to the supplier booking slice
  (hold + confirm + allotment consumption under a lock).
- **B4 child price on `sv:` per-person lines only.** Supplier child rate > contract child % > policy % per service type
  (< 100) > adult price with an age note. `tp:` lines keep the pricing rule's sell-side `child_pct` (AA-1075):
  applying B4 there too would discount a child twice. Rooms stay per room (hotel child policy = hotel slice).
- **Child rate without ages:** a quote carries no ages, so among child rates of several bands the one reaching the
  oldest age wins (`RATE_ORDER_MANY`): the oldest child is never under-priced.
- **Per-service-type ratio = pricing policy `child_price_pct_by_service_type`** (type `amount_map`, choices = the five
  service types, 0-100, approver group pricing, seeded 100 = today's behaviour). The existing `amount_map` type needs
  no frontend change; 100 doubles as "no default ratio" (adult price + age note). Per supplier = the contract's
  `child_pct` (contracting sets it on the draft, a second person publishes it).
- **B7:** `net_amount` stays the only price read. `published_amount` + `commission_pct` are kept as source numbers;
  the net is derived half-up to the cent; the CHECK holds the same equation.
- **Erasure (DM-6.7, review fix):** `supply_restrictions.note`, `reject_reason`, `withdraw_reason` and `end_reason`
  are `pii:free_text`. The bk-060 guard trigger lets `bk_owner` set them to `[redacted]` on any row (a closed
  stop-sale, a term of a published contract) when nothing else but `updated_by` / `updated_at` changes, like the
  bk-054 branch. Any other text, or a redaction mixed with another change, is still refused.

## Changed (vs. the issue text)

- The issue's T13 part (four roles, no `ops`, hide `content_creator`) is AA-1150; this lane does only the stop-sale

- No admin UI in this PR: lane l6 (AA-1128) is rewriting every Booking supply page into the i18n phrasebook in the
  same wave; a contract-page panel now would conflict file by file. Only the policy page label of the new parameter
  is added. Follow-up: the terms + restrictions + stop-sale panel on the contract page after l6 merges.

## Tradeoffs

- Restrictions are scoped to a contract, so a stop-sale needs a published contract; a supplier with no contract cannot
  get a stop-sale (it cannot be sold either: no rate).
- The policy `amount_map` needs a value for every service type; "no ratio" is spelled 100.
- One more query per quote (restrictions for the quote's components and dates) plus a usage query only when an
  allotment applies; the terms query only when an `sv:` line has children and no child rate.
