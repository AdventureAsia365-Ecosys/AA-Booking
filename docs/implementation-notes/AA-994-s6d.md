# AA-994 S6d — Booking pages on the kit frame and form controls, plus the two open Figma gaps

Root ADR 0016, plan row S6d (`AA-Ecosys/docs/audits/2026-10-27-S252-aa994-design-system/plan.md`), kit form controls
from CIS S6a (`ui/core/FormControls.tsx`, already synced into `frontend/ui/core/`). Also the two items left open by
`AA-Ecosys/docs/audits/2026-10-28-S254-booking-figma-audit/gap-status-S258.md` ("Still open" 1 and 2).

## Decisions

- **Raw `<main>` → PageFrame (all of them).** Three shapes, each mapped to one frame with the same pixels:
  - `aa-admin-main … px-8 py-6` (+ an inner `mx-auto max-w-[…]` column) → `<PageFrame width="full">`: the Booking
    gutter (24 px 32 px), the inner column kept as it was. `px-4 py-6 sm:px-8` is the same frame (the phone rule in
    `ui/local/shell.css` sets 16 px with `!important` below 768 px either way).
  - `aa-admin-main flex-1 overflow-y-auto` with an edge-to-edge header band (DetailHeader, the trip case and new case
    bands, the supplier form) → `<PageFrame bleed>`, a new prop of the Booking wrapper (`ui/booking/PageFrame.tsx`):
    full width, padding 0. The phone rule still gives these pages their 16 px phone gutter, as it did the raw `<main>`.
  - The loading skeletons had `aria-busy` / `aria-label` on the `<main>`; the kit frame takes no ARIA props, so they
    moved to an inner `role="status"` wrapper (no visual change).
  - The three pages outside the staff shell (sign-in, session notices, 404) are full-screen centred screens, not
    shell pages. They render `ui/local/StandaloneFrame.tsx`, a server component in the shell layer (out of the kit lint
    scope, like `AdminShell`), not the kit PageFrame (whose `.aa-admin-main` class would pull in the shell gutter
    rules). CIS has no such pages in its lint scope.
- **Form controls: all 190 raw controls migrated, rule 8 on with no baseline.** A codemod (kept outside the repo)
  swapped `<input>` → `Input` / `Checkbox` / `Radio`, `<select>` → `Select`, `<textarea>` → `Textarea`; `type="file"`
  stays (the rule allows it, no kit file picker yet). Because nothing is left to suppress, `STAGED_RULES` is on for
  `app/**` and `ui/booking/**` without adding entries to `eslint-suppressions.json`, so the "suppressions do not grow"
  step passes as is and Booking does not need a copy of CIS's `kit-new-rules.mjs` (and no CI change).
- **Look:** the kit controls draw their look inline (40 px, radius 8, card background, 1 px line, focus / invalid /
  disabled states). The Booking class constants (`inputCls`, `fieldCls`, `textareaCls`) are now layout only
  (`w-full`, `min-h-[96px]`); the 36 px controls (`h-9` constants in billing, the B2B desk, the case suppliers tab,
  the price panel) became `size="sm"` (36 px, 13 px text). Inline padding wins over Tailwind padding, so the search
  boxes with a leading icon (`pl-9`) and the policy picker (`pr-8`) carry `style={{ paddingLeft: 36 }}` /
  `paddingRight` instead; the price panel's note keeps 32 px / 12 px through `style`; the sign-in boxes keep their 44 px
  through `style` (the password box keeps room for the show / hide button).
- **Labels:** the two local field wrappers (`(staff)/_parts/FormField.tsx` and `cases/_parts/fields.tsx` `Field`) now
  render the kit `Field` (same label / hint / error look, which S6a took from Booking's §4 "Forms"), so every control
  in them gets `aria-describedby`, `aria-invalid` and `aria-required` from the Field.
- **`TimeField`** keeps its 24 h text parsing; its text box is the kit `Input` (the invalid border now comes from
  `aria-invalid`, so the inline danger border is gone).
- **Hand-styled buttons: only the three that are kit buttons in shape** (sign-in submit, "Mark as read", "Sign out").
  The other 66 are link-style text buttons, list option rows, underline tab bars, chip toggles, icon buttons and a
  menu trigger with `aria-haspopup` / `aria-expanded`: the kit `Button` has no `className`, no ARIA passthrough and no
  link / icon / chip variant, so moving them now would either change their look or drop ARIA. They stay suppressed
  until the core gains those variants (a CIS core change, then a sync).
- **Hotels grid (S254 audit #19).** `/hotels` opens on a photo card grid (Figma HOTEL MANAGEMENT); a Grid / Table
  switch (kit `Tabs` in the header actions, `?view=table`) keeps the same query, filters, paging and CSV. A card: the
  first active supplier photo (or the same neutral tile as `CisPhoto`, "No photo"), photo count chip, place chip
  ("Hoi An, Vietnam"), name (opens the drawer), code + style, stars, supplier, room types / rates in force, status,
  "Updated … ago", and the table's row menu. The grid has its own small pager (range, page size, previous / next) on
  the same URL state as the table's server pagination. CSV in grid mode = the current page (as the Countries grid).
- **Backend for the grid:** `GET /booking/hotels` rows gain `photo_count` and `cover_photo_url` (presigned, the first
  active photo in the media list order). One grouped read per page on `booking.entity_media` (index
  `entity_type, entity_id, created_at`), presigning only the first key of each hotel. Fails soft: a database error
  leaves 0 / null on every row (logged), no bucket configured leaves the count and a null cover. Supplier photos are
  internal (bk-023); showing them to staff in the list is the same exposure as the hotel drawer's photo strip.
- **Billing row menus (S255 rescore).** Invoice rows: View invoice, Open trip case, Cancel invoice (when the row's
  `actions.cancel` is true; the same reason dialog as the invoice page). Payment rows: View payment, View invoice,
  Download evidence (the evidence file, else the newest attached file; 5-minute link, as on the detail page), Void
  (when `actions.void`; the detail page's `VoidPaymentDialog`). "Download PDF" is not offered: Booking has no invoice
  PDF yet (the invoice page says "PDF: coming later"), so the menu shows it never rather than a dead item.
- **Backend for the invoice menu:** `GET /booking/invoices` rows now carry `actions` (the detail's `actions()`), so the
  list never guesses permissions client-side. Payment list rows carry `actions` and `evidence_file_id`, but `files`
  is always `[]` on the list (only `GET /booking/payments/{ref}` reads the attached files; see review fix 2).

## Changed (vs the plan row and the gap note)

  files. All are done. Buttons: 3 of 69 (see Decisions).
- `docs/figma-coverage.md`: HOTEL MANAGEMENT (and the two misfiled COUNTRY MANAGAMENT-2/-3 rows) and PAYMENT &

  The fixture hotels carry photo counts and covers (some without, for the neutral tile).

## Tradeoffs

- Kept the layout class constants instead of deleting them: one place per form still sets width / min-height, and the
  diff stays a tag swap. They can go when the forms move to kit `Field` everywhere.
- A list photo is a presigned URL per hotel per list read (signing is local, no S3 call). Alternative was a thumbnail
  pipeline; not worth it for an internal staff list.
- The grid's pager is a small local component, not the kit DataTable's (the kit has no stand-alone pager). If CIS or
  Partner need one, upstream it then.

## Should know

  states and the kit placeholder colour; checkboxes / radios are 16 px accent boxes; text areas whose class had no
  min-height now start at 3 rows. Sizes are kept (40 / 36 / 44 / 32 px as before).
- The invoice and payment tables gained an Actions column (sticky at the right from 768 px, `bk-dt-sticky-end`, like
  hotels): the S254 "fits 1440 with 20 px slack" budget of those two tables should be re-measured with the layout-mock
  suite (not run here: low-RAM machine, no Playwright browsers).
- Not run locally: backend integration tests (need Postgres), `next build`, the Playwright layout-mock suite. Run:

## Review fixes (independent review, verdict "block")

1. **Form date boxes rendered bare (high, confirmed).** The kit `DateField` has no look of its own: its text box takes
   only the caller's `style` / `className` (FilterBar passes `filterControlStyle`). S6d made the shared form class
   constants layout only (`inputCls` / `fieldCls` = `w-full`), so 20 form date boxes (policy, bill, payment, invoice,
   proposal, supplier booking, case, trip-plan price matrix, contract, rate, trip-check drawers) lost border,
   background, height and padding under Tailwind preflight. Fix: `ui/booking/FormDateField.tsx` wraps the kit field
   with `controlStyle(size)` + `CONTROL_CLASS` (the same look and focus / invalid / disabled / placeholder states as
   the kit `Input`), and `@/ui` exports it as `DateField` (the same pattern as the Booking `DataTable` wrapper), so no
   page can pass a date box without the look again. `size="sm"` (36 px) where the sibling Inputs are small (billing
   payment / bill / invoice dialogs, the case suppliers tab); the proposal modal's extra `h-10` is gone (40 px is the
   default). FilterBar keeps importing the core field directly (filter look, 36 px).
   - Decision: a Booking wrapper rather than a per-page `style={controlStyle()}`: one place, and a future page cannot
     forget it. The kit core cannot be changed here (ADR 0016); if CIS or Partner want the same, upstream a `size` /
     form look on the core `DateField` in CIS and drop the wrapper after the sync.
   - Should know: the `CONTROL_CLASS` state rules are a stylesheet the kit `Input` / `Select` / `Textarea` inject; every
     form with a DateField today also renders one of them, so the states apply. A form with only a DateField would keep
     the look but lose the focus colour (the invalid border still comes from the field itself).
   - Guard: `e2e/layout/case-workspace.spec.ts` (trip-check drawer) asserts the drawer's due-date box is 40 px with a
     1 px solid border and a non-transparent background. Run locally with a fresh `next build`: passes.
2. **Payments row menu "Download evidence" never appeared (medium, confirmed).** `GET /booking/payments` rows call
   `payment_out(r, staff)` without files, so `files` is `[]` on every list row and the item was dead. Fix (frontend
   only, no extra read on the list): `paymentEvidenceFileId()` (`ui/booking/paymentEvidence.ts`) takes the row's
   `evidence_file_id` (an `ops_files` id; removing that file clears it, so no stale link), else the newest attached
   file for a detail-shaped row. Unit test `ui/booking/paymentEvidence.test.mjs` covers the list shape (`files: []`
   with evidence), precedence, the fallback and no evidence. A non-evidence attachment without `evidence_file_id`
   is not offered from the list (only the evidence matters there; the detail page lists every file).

### Layout-mock run (whole suite, local, after the fixes)

278 passed, 3 failed: `billing-invoices fits 1440` (light, dark) and `fits 1400` (light). The invoices table is
min-content 1082 px against a 1078 px frame at 1440 (1038 px at 1400; the check wants 20 px to spare). Cause: the
Actions column (94 px) added in S6d, as "Should know" above predicted; not touched by the review fixes. Column widths
at 1400: Invoice 108, Trip case / customer 198, Issued 120, Next due 124, Total / paid 168, Left to pay 160, Status
149, Actions 94. At 1400 about 64 px must go (the table's own `tableMinWidth` is 1000). Options for the orchestrator:
show "Sent <date>" as the Invoice cell's second line and drop the Issued column (CSV keeps its own Issued column), or
fold Issued into the details drawer from 1200 up as well. Left open here because it changes the table's design.

## Orchestrator fix: invoices table width (S259)

- The separate Actions column pushed `/billing` invoices past the AA-996 budget (1440: 1082 > 1078; 1400: 9 px of the
