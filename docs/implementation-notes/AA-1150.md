# AA-1150 — Lean staff roles step 1 (Booking part)

Session S286 (lane l1-roles-step1). The CIS part (Staff page presets, retired `content_creator` grant) is a separate PR
in AA-CIS-App with its own notes file.

## Decisions

- **Finance reads (L7a)**: `finance` joins `trip_case.read`, `pricing.read`, `supply.read`, `ops.read`, `bill.read` and
  `catalog.read`. Nothing else changes for finance: `payout.write` stays admin only (tech lead decision Q4, S285), and
  no write right is added (a unit test pins finance's full permission list).
- **Three approval capabilities**: `supplier.activate`, `contract.publish`, `stop_sale.approve`, each `admin` +
  `contracting`. Built-in roles keep every right they had, so the A10e-2 pricing checker (`booking-contracting`,
  publishes the maker's synthetic contract) and the CIS "Pricing team" preset (Booking `contracting`) are unchanged.
- **Where the checks sit**: the service functions, before any read (`suppliers.service.set_status` for `active`,
  `suppliers.service.update_contract` for `status=published`, `supply.restrictions.decide_stop_sale` for approve /
  reject and `approve_end`); the `/end` route also has the `require("stop_sale.approve")` dependency. A refusal is 403
  `forbidden`, like every other missing permission.
- **Creating a supplier** (review fix): `create_supplier` writes `status` explicitly, `active` for a holder of
  `supplier.activate` and `inactive` otherwise. The column default is `active` (bk-008), so without it a maker with
  `supply.write` alone would get an active supplier on create and skip the approval. Admin and contracting hold the
  capability, so their creates (and the E2E pricing flows) still start active; the create audit row carries `status`.
- **What stays a write**: deactivating a supplier, expiring a contract, setting a stop-sale, withdrawing one's own
  stop-sale, asking to end one and taking that request back. They are the maker's actions.
- **Season calendar stop-sale ranges** (`seasons_admin`): approving / rejecting a `stop_sale` range, or its removal,
  also needs `stop_sale.approve` (on top of `season.approve`), so a stop-sale cannot be lifted through the calendar
  path by a role that cannot lift it on the contract.
- **Label**: the built-in `contracting` role shows as "Product & operations" (`frontend/lib/rbac.ts`, VI "Sản phẩm &
  điều hành"). The role code stays `contracting` (group `booking-contracting`).

## Tradeoffs

- No built-in role lacks the new capabilities today, so the refusal is proven with a test role ("maker") that holds
  every contracting right except the three. The real maker role arrives with custom roles (the follow-up issue on roles
  as data); until then the split changes no live behaviour.
- Finance lands on the trip-case dashboard (it can now open `/cases`) instead of the catalog card; a finance home
  (bills due, payments to approve) belongs to the My work slice.
- `content_creator` stays a valid Booking role and group here (existing rows keep working); the CIS Staff page stops
  granting it and its Sync removes the group (CIS PR).

## Should know

- Hotel and service activate (`/hotels/{ref}/activate`, `/services/{ref}/activate`) stay `supply.write`: they reopen a
  record of an already-active supplier; the supplier activation is the approval gate.
- The "Contracting adds ..." empty-state sentences on the hotels, services, suppliers and departures pages still say
  "Contracting"; renaming them is copy only (follow-up).
- `bill.read` also opens supplier bill and payout documents (`app/ops/files.py`: `supplier_payout` reads with
  `bill.read`), and `ops.read` the supplier booking documents (vouchers); finance reads them from now on. Writing a
  payout stays `payout.write` = admin.
- The integration test `test_aa1074_finance.py::test_fx_snapshots_and_case_costs` fails on a machine whose local date
  differs from the UTC date (it compares `date.today()` with the database day); CI runs in UTC. Unrelated to this
  issue; run local integration tests with `TZ=UTC`.
