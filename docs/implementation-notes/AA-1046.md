# AA-1046 R4b part 1: retire the B2C half of Booking (S271)

Root plan: AA-Ecosys `docs/audits/2026-11-05-S270-aa1037-b2c-drop-dryrun/README.md` (sections 2, 4, 8). Two PRs here,
in this order: the **code PR** (this file's first part: no reader or writer of the objects bk-045 drops is left) and
the **migration-only PR** with `migrations/045_aa1037_retire_b2c.sql` (destructive), stacked on it. Part 2 of AA-1046
(VAT e-invoice provider API) is another lane.

## Decisions

- **Remove, not hide.** Deleted: `app/routers/customers.py`, `billing.py`, `customer.py`, `app/customers/`,
  `app/auth/customer.py`, `app/ops/invoices.py`, `payments.py`, `my_payments.py`, `app/inquiry/intake.py`,
  `app/inquiry/contract.py`, `app/contracts/` (the vendored inquiry schemas only the parser read),
  `app/notifications/staff_email.py`, and on the staff admin the Customers pages, the customer invoice and payment
  pages and tabs, the case Billing tab, `SendProposalModal`, `/cases/new`, the customers search of the command
  palette. Kept: `app/inquiry/leg_keys.py` (reads kept legs), `app/retention/redact.py` (the kept inbox rows are still
  redacted, DM-6.6), `app/ops/money.py` (shared by supplier bills and agency billing).
- **b2c cases stay readable and read-only.** The guards of `app/b2c.py` lost the switch: a write on a `b2c` case is
  always 410 `b2b_only`. Lists keep showing every channel (the `channel` field tells them apart); no customer column
  is returned any more (`customer_id`, `customer_*` and the case `money` badge are gone from the shapes). The staff
  admin labels a b2c case "Traveller (B2C history)" (`ui/booking/caseFacts.ts` `casePartyLabel`).
- **`POST /booking/trip-cases` and a new case from a trip plan stay as 410 routes** (body-less / `trip_case` only):
  a staff-made case was always a B2C case. Keeping the route answering 410 is clearer for a caller than a 405.
- **Send to the customer is removed** (route, service, modal, buttons). A B2B case's proposals belong to the partner
  API (409) and a b2c case is read-only (410), so no case could reach it. Approve stays (it reads no dropped table).
- **The worker cancels leftover rows of the retired kinds** (`b2c.RETIRED_KINDS` = `bk_inquiry_pull`,
  `bk_inquiry_process`, `bk_notify_email`) through the existing `disabled_kinds` path. `bk_inquiry_pull` stays in
  `DEPLOY_GATE_EXEMPT` so the deploy-gate answer (read by Deploy Dev) keeps its shape.
- **Settings removed**: `b2c_intake_enabled`, `cognito_external_issuer`, `cognito_tripplanner_client_id`,
  `cognito_booking_customer_client_id` (an env value left in the task definition is ignored, tested).
- **Staff permissions stay in `app/auth/staff.py`** (`customer.*`, `billing.*`, `payment.verify`): no route checks
  them any more, but the role table is auth-sensitive and the staff admin's frozen mask still names them; dropping
  them is a separate, reviewed change.
- **`B2C_INTAKE_OPEN` is the constant `false`** in `frontend/lib/config.ts` (no env read). The `open` parameters of
  `ui/booking/b2cFrozen.ts` stay so the per-case rules read the same; the open-only layout tests are removed.
- **API break is intended**: `/booking/customer/v1` is a public path for the OpenAPI gate; the PR needs the
  `api-breaking` label (or the `feat!:` title it has).

## Changed

- `app/b2b/holds.py`: the B2B confirm insert no longer names `trip_cases.customer_id` (bk-045 drops the column).
- `app/ops/track.py`: the money track is gone; a kept b2c case left in a money status is off the track.
- `app/ops/files.py`: entity `payment` (customer payment evidence) has no permission any more (403); the files stay.
- `app/ops/lifecycle.py`: the customer payment reminders (`payment.due_soon`, `invoice.overdue`) are gone.
- Trip case list / detail, versions list, trip checks, staff detail: no customer join. The `q` search of the case
  list is the case code only; of the versions list the case code and the version title.
- Tests: the unit and integration tests of the removed code are deleted; `tests/unit/test_aa1046_b2c_retired.py`
  covers the removed routes (404 / 405), the 410 on a new case and on b2c case writes, the retired kinds, the B2B-only
  jobs. The integration helpers (`tests/integration/ops.py` `insert_b2c_case`, `tests/integration/handoff.py`) write
  kept b2c cases in SQL on either side of bk-045 (before it they add the customer the old CHECK needs; after it there
  is no `customer_id`), created at a fixed date before the drop. Modules that drive the operations services over HTTP
  on the sold b2c case use the conftest fixture `b2c_guard_off`.

## Tradeoffs

- Reading-only staff pages for the B2C records (customers, invoices) are gone rather than kept read-only until the
  drop: the drop follows this build, and a page over a table that is about to go would 500 after it.
- The archived customer money and payment evidence are not readable in the app (owner-only archive, DM-7.1); an
  accountant request goes through a reviewed run-script.

## The migration PR (bk-045)

Decisions:

- **From the S270 draft, unchanged in substance.** `migrations/045_aa1037_retire_b2c.sql` is the root draft
  (`docs/audits/2026-11-05-S270-aa1037-b2c-drop-dryrun/migrations/bk_NNN_aa1037_retire_b2c.sql`) with the key, the
  header and two fixes the migration guard asked for: the registration text has no `;` (the guard's regex stops at
  one) and the two views the drop rebuilds (`v_trip_check_board`, `v_ops_data_totals`) get `REVOKE INSERT, UPDATE,
  DELETE … FROM booking` (views are read-only for the app role). The root draft carries the same two fixes.
- **Pins are filled in this PR, before merge.** `pins jsonb := '{… null …}'` in section 0: every `null` fails closed,
  so the file cannot apply until the orchestrator pastes the `DRYRUN_PINS` JSON of a fresh DRY RUN (count + md5 over
  non-personal columns, the same `PIN_COLUMNS` as the script, harness-checked). A merged file is copied to
  AA-CIS-Infra and never edited, so the paste happens on this branch.
- **No strict `CHECK (channel = 'b2b')`.** The kept b2c cases must stay updatable (DM-6.7 erasure redacts their free
  text in place; retention jobs touch them), and a CHECK is re-checked on every UPDATE of the row, even `NOT VALID`.
  bk-045 instead swaps `trip_cases_channel_chk` for: `b2b` with a `party_tenant_id`, or `b2c` created before the
  apply-time literal (a new b2c row cannot be written, an old one can be updated).
- **Old migrations are not re-runnable after bk-045.** bk-001..bk-036 create or grant objects bk-045 drops; the
  conftest re-run rule (`SUPERSEDED_BY_BK045 = frozenset(range(1, 37))`) skips them once bk-045 is registered, and the
  modules that re-applied one of them directly skip that test after the drop. DB Migrate applies each key once, so this
  only touches the tests.

Tests: `tests/integration/test_bk045_retire_b2c.py` rebuilds the schema to bk-044, seeds b2c and b2b rows, runs the
DRY RUN script (`tests/integration/b2c_dry_run.py`, a byte copy of the root script) for the pins, applies bk-045, and
checks the archive count, the kept rows, the dropped objects, the new CHECK and the fail-closed pins; it restores the
full schema at the end. Integration 544 passed, 13 skipped (the re-run skips above); the migration preflight with the
AA-CIS-Infra tools reads bk-045 as destructive, lint ok.
