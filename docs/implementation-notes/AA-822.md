# AA-822 — Booking wave 2a: suppliers + supplier contracts (bk-008)

Session S237 (Claude Code). Sources: Linear AA-822, S237 lane plan (`AA-Ecosys/docs/audits/2026-10-14-S237-lane-backlog/`,
booking lane item 3, locked decisions D1–D9), S236 UI spec (`booking-ui-spec/ui-spec.md` §3, §6.3, §8; module spec
`08-suppliers.md`), ADR 0005 decisions 1, 2, 8.

Delivery follows D8: branch `feat/aa-822-bk-008` carries the migration file only (plus its schema test and these
notes); `feat/aa-822-suppliers` is stacked on it with the API, the frontend and the
`REQUIRED_SCHEMA_VERSIONS` bump.

## Decisions

- **Number bk-008, independent of bk-007.** bk-007 (AA-810 policy approvals) is written in parallel. bk-008 touches
  only bk-001 (schema, role, `set_updated_at`), bk-003 (`staff_users`) and bk-005 (`countries`), and grants per
  table (never `ON ALL TABLES`, which would re-open UPDATE/DELETE on the bk-004 append-only pricing tables). bk-007
  merged to main (#8) and was applied on Dev while this was in progress, so the branch was rebased on it and the
  guard's `RESERVED_ON_OTHER_BRANCHES` stays empty.
- **Write permission = admin + contracting, sales read** (lane plan item 3, module spec 08 conflict 3, ADR 0005 d8).
  The Linear text says "admin/sales write"; the lane plan locked in S237 Gate 1 and the UI spec both say contracting
  owns supply. Followed the spec; flagged for Nghiep below.
- **No delete, deactivate only** (lane plan "changes_vs_scout" 8). Role `booking` has no DELETE on either table. The
  spec's `DELETE …/{id}` soft delete is not built.
- **Deactivate is refused while a published contract is in force *or upcoming*** (`valid_to` NULL or ≥ today, UTC
  date). The lane text says "in force"; an upcoming published contract is just as binding, so it blocks too.
- **Categories = `TEXT[]` with a CHECK** over hotel / transport / guide / entrance / activity / meal (Q20), 1–6
  values. No "awaiting document check" state (Q20 recommendation).
- **`destination_id` has no FK.** It is a CIS place (`catalog.v_destination`, golden record `shared.destinations`);
  role `booking` has SELECT on the catalog views (CIS 225), not REFERENCES on `shared`. The API validates it.
- **`country_code` → `booking.countries`** (bk-005 ISO list). Added `MN` (Mongolia): AA sells Mongolia and the
  bk-005 list stopped at 16 Asian countries. Other countries are one `INSERT … ON CONFLICT DO NOTHING` away.
- **Human code `SUP-000123`** like `CUS-` (bk-005), used as the audit `entity_label`.
- **Duplicate guard:** unique on `(lower(btrim(company_name)), coalesce(country_code, '--'))`. The same name in two
  countries is allowed (chains).
- **Contracts: draft → published → expired, maker-checker on publish.** ADR 0005 d8 ("one person uploads or edits,
  another publishes") covers supplier contracts. The DB CHECK `supplier_contracts_maker_checker_chk` refuses a
  publisher who is the last writer of the draft terms (`coalesce(updated_by, created_by)`; the API sets `updated_by`
  on create and on every draft edit, publishing does not touch it). Not "creator OR last editor": with that rule a
  checker who corrects a typo in A's draft becomes a second maker and a two-person team is stuck until a third
  person publishes. With "last writer", A checks B's correction and publishes; every published version of the terms
  was seen by someone other than its last author.
- **A published contract is fixed** (ADR 0005 d2 "never overwrite"): trigger `supplier_contract_lock` allows only
  published → expired (with `expired_by/at`); a draft cannot jump to expired; an expired contract never changes. New
  terms = a new contract.
- **Publishing is a move on its own, also in the DB** (review fix). The lock trigger refuses a draft → published
  UPDATE that also changes the terms or `created_by` / `updated_by`; otherwise one UPDATE could rewrite `updated_by`
  (or the terms) and publish in one go, side-stepping the maker-checker CHECK. The API already sends the status alone.
- **`pii:` / `conf:commercial` column tags** (review fix, data standards DM-6.1): `contact_name` (pii:name),
  `contact_email` / `contact_phone` (pii:contact), supplier `internal_notes` and contract `payment_terms`,
  `cancellation_policy`, `notes` (conf:commercial).
- Contract columns beyond the spec sketch: `title` (required, the name staff see in the Contracts tab),
  `reference` (supplier contract number / document reference — the Linear "document ref"; upload is out of scope),
  `notes`. `valid_to` NULL = open-ended.

## Changed (vs. the Linear issue / lane text)

- Linear sketch `kind`, `payment terms`, `currency` on the supplier: kind became `categories[]` (Q20); payment terms
  and currency live on the contract (ADR 0005 d2), not on the supplier.
- RBAC: admin + contracting write (not admin + sales), see Decisions.

## Tradeoffs

- Maker-checker on contract publish means a single admin cannot publish alone: live verification needs two staff
  accounts (same as AA-810 rules / FX approvals).
- `TEXT[]` categories instead of a join table: simple filter (`&&`, GIN index) and enough for 6 fixed values.

## Should know

- Migration-only PR contents: `migrations/008_suppliers_contracts.sql`, `backend/tests/integration/test_bk008_schema.py`
  (DB rules: checks, no delete, maker-checker, lock trigger) and these notes. No `REQUIRED_SCHEMA_VERSIONS` change
  (D8): that bump lives in the code branch, which must merge only after bk-008 is applied on Dev.

# Code branch `feat/aa-822-suppliers` (API + staff admin, stacked on bk-008)

## Decisions

- **Permissions `supply.read` (admin, sales, contracting) and `supply.write` (admin, contracting)** in
  `app/auth/staff.py`. `content_creator` reads nothing here (UI spec §3: A C, S(r)).
- **Endpoints** (UI spec §6.3 without the soft `DELETE`): `GET/POST /booking/suppliers`, `GET /booking/suppliers/summary`
  (KPI strip, module spec 08 conflict 8: total / active / inactive / countries / published contracts ending within 30
  days), `GET/PATCH /booking/suppliers/{id|SUP-code}`, `POST …/deactivate|activate` (optional `reason`, kept in the
  audit summary), `GET/POST …/{ref}/contracts`, `GET/PATCH /booking/contracts/{id}`. A contract PATCH either edits a
  draft's terms or carries `status` (`published` / `expired`) alone (422 `status_with_changes` otherwise).
- **List paging is offset-based** (`limit`/`offset`/`total`) like `/booking/customers`, not the keyset cursor of the
  audit log: the directory is small and the kit DataTable shows "page x of y" (lessons: server pagination and
  server-side filter options — the country filter lists `/booking/countries`, not the countries of the page).
- **Place check against `catalog.v_destination`** (`app/catalog.py`): writes fail closed (422 `unknown_destination`,
  503 `catalog_unavailable` when the view or grant is missing), reads fail soft (the name is omitted and the page says
  the catalog cannot be read). Each catalog query runs in its own (sub)transaction so a missing view cannot abort the
  caller's write transaction. `v_destination.country` is a country *name*; it maps to ISO-2 through
  `booking.countries.name`. When the place maps to a country, an empty supplier country is filled from it and a
  different one is refused (422 `destination_country_mismatch`).
- **Place picker endpoint `GET /booking/catalog/destinations`** (any active staff, `q` / `country` / `limit` ≤ 50).
  It is the first route of the catalog router that AA-679 will extend.
- **Maker = last writer of the draft** (`coalesce(updated_by, created_by)`; the API sets `updated_by` on create and on
  every draft edit). Same rule in the API (403 `maker_checker`) and the DB CHECK. The Contracts tab disables Publish for
  the maker ("needs a second person").
- **Contract phase** is computed in SQL on the UTC day: `draft | upcoming | in_force | ended | expired`. A published
  contract past its `valid_to` is `ended` until someone expires it; nothing expires automatically.
- **No contract on an inactive supplier**: create and publish answer 409 `supplier_inactive`.
- **Frontend**: `/suppliers` (KPI strip, search, status / category / country / sort filters, server pagination, row
  menu View / Edit / Deactivate|Activate), `/suppliers/new` and `/suppliers/[id]/edit` (full-page form as in Figma 08,
  sections Basic information / Contact / Location; only name + one category required; Description is "Internal
  notes"; City is a CIS place typeahead with the From CIS tag), `/suppliers/[id]` (header + tabs Profile / Contracts /
  Rates / Bookings / Bills; the last three are frames). Contract new / edit is a drawer; publish and expire are confirm
  dialogs. URLs use the `SUP-` code. Nav entry `Suppliers` is `shipped: true`.
- **`REQUIRED_SCHEMA_VERSIONS` adds `bk-008`** after `bk-007` (listed by AA-810 #7, applied on Dev).

## Changed

- No `DELETE /booking/suppliers/{id}` (spec §6.3 lists a soft delete): suppliers deactivate only (lane plan, 08
  conflict 4).
- No CSV export on the supplier list (08 conflict 9 wants it admin/contracting-only and audited; left out of this
  slice).

## Tradeoffs

- Offset paging counts the whole filtered set on every page: fine for a supplier directory (hundreds of rows), not for
  the audit log.
- The contract "Entered / published by" column shows the last writer, not every editor; the audit log keeps each edit.

## Should know

- **Merge order (D8):** this branch must merge only after bk-008 is applied on Dev: `/booking/health/ready` needs bk-007
  and bk-008. It is stacked on `feat/aa-822-bk-008`; once that merges, rebase on main (the migration commit drops out).
- Live verification of publish needs two active staff with `supply.write` (one enters, the other publishes).
- Tests: `tests/integration/test_bk008_suppliers_api.py` (HTTP over the real DB, stub `catalog.v_destination` in
  `tests/integration/stub_catalog.sql`, applied after the migrations because the grant needs role `booking`),
  `tests/unit/test_suppliers.py` (route permissions, body validation, catalog fail-closed / fail-soft).
- **Review fixes (S237 adversarial review).**
  - Publishing now locks the supplier row (`FOR UPDATE`) like deactivate and create-contract do. Before, a publish
    racing a deactivation could leave an inactive supplier with a live published contract.
  - Clearing `country_code` on a supplier whose CIS place maps to a country is a no-op (the place's country stays).
    Before, the derived value was dropped when it equalled the stored one and the column was written NULL.
- **Known gap, CIS side:** `catalog.v_destination` (CIS 225) lists every `shared.destinations` row, including rows
  that CIS 226 marked `duplicate_of` another place, and does not expose `duplicate_of`. The picker can therefore show
  and store a non-survivor place id. Fix belongs to a CIS catalog migration (expose `duplicate_of` or filter it out);
  Booking then filters the picker and resolves to the survivor.
