# AA-1187 — Supplier pack and tour pack importers (Booking part)

Step 1 only (S296): the Booking data-entry bug fix that must ship before the price setup maker enters data. The
supplier pack importer (step 2) and the tour pack (step 3) come in later sessions and add their sections here.

## Decisions

- **Two places dropped a hotel night's board, both are fixed.** The S295 data audit named the workbook import
  (`price_import.match` built each component without `meal_plan`, so `plan_components.replace_components` wrote NULL =
  the default BB). Reading the code found a second one: the Price setup drawer's Save sends the whole set through
  `ui/booking/priceWorkbench.ts mergeComponents`, which also kept only day + item. Both now carry the board.
- **`Meal plan` column on the Components sheet, empty = keep.** The issue offered "add a column" or "keep the
  existing value when tour, day and room match"; this does both: a value sets the board, an empty cell (or a file made
  before the column existed) keeps the board the same night has (same plan, day and room type id). That matches the
  Tours sheet's "Sellable empty = unchanged". A night that is new (another day or another room type) gets none, so the
  default BB, as on the form. To go back to the default, type `BB`.
- **Code or name.** The cell takes `RO`/`BB`/`HB`/`FB`/`AI` or the names the rate drawer shows (Room only, Bed &
  breakfast / Bed and breakfast, Half board, Full board, All inclusive), case, spaces and "&" ignored; anything else is
  an `invalid_value` problem for that row. A Meal plan on a service row is `invalid_meal_plan` (the same rule as
  `PUT …/components`).
- **A board change is a change.** `_same_components` compares the board too (as `plan_components._state` already
  did), so the dry run's `components_changed` says when only a board changes and the same file again writes nothing.
- **No migration, no new setting.** `trip_plan_components.meal_plan` exists (bk-069); nothing here is a threshold.

## Changed

- `backend/app/catalog/price_import.py`: `Meal plan` column (parse, check, match keeps the current board, export
  prefills it, README line).
- `frontend`: `PlanComponent.meal_plan` in `lib/api/priceWorkbench.ts`; the drawer's `currentRef` and
  `mergeComponents` keep the board (an accepted suggestion for a night the plan already has keeps that night's board).
- Booking `CONTEXT.md` (bulk workbook paragraph). The root guide `docs/guides/booking-price-setup.md` and its `.vi.md`
  get the column in a root PR of the same lane.

## Tradeoffs

- "Empty = keep" means an empty cell cannot clear a board; typing `BB` does (BB is the default anyway). The other
  reading (empty = default) is exactly the bug: every old file and every hand-typed row would reset the boards.
- The board is matched by plan + day + room type id. Changing the room type of a night drops its board (the new room
  is a new item); the drawer behaves the same.
