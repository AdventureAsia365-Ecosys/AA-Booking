# AA-1034 R0 — bk-036: REVOKE INSERT on the B2C customer tables (lane l6, migration-only PR)

Root ADR 0019 d8 (B2B-only ecosystem model, approved S265). Record: root
`docs/audits/2026-11-03-S265-ecosystem-restructure/` (README §11 R0, clarifications.md, adr-0019-draft.md).

## Decisions

- **Tables** (grants read from root `docs/architecture/db-schema-reference.md`, verified 2026-11-02): `booking.customers`,
  `booking.customer_identities`, `booking.customer_otps`, `booking.customer_sessions`. These are every `booking.customer*`
  table; `booking.invoices` (B2C-only too) is not a traveller PII table and stays as it is (frozen with d8, dropped later).
- **Role**: `booking` (the Booking runtime login). Only INSERT is revoked. SELECT, UPDATE, DELETE stay for staff reads,
  `bk_retention_job` redaction / deletion and erasure requests. `customer_identities` keeps its bk-024 shape (SELECT +
  column UPDATE (customer_id), never DELETE).
- **Guard**: "a row inserted in the last hour" is read per table from `created_at`, and only while INSERT is still
  granted on that table. So the first apply refuses while the intake still writes, and a re-run (INSERT already
  revoked) is a no-op even with recent rows.
- **Class**: contract (no `-- migrate:` line): it changes privileges of existing tables (root ADR 0017 d3). MIG-4:
  this PR carries the file and its tests only; the code PR (flag) follows. No readiness key: no code reads its shape.

## Changed

- `migrations/036_b2c_customer_insert_revoke.sql` (new).
- Tests: `tests/integration/test_bk036_schema.py` (registered, INSERT refused 42501, UPDATE / DELETE kept, re-run
  no-op, guard per table, wrong role refused).
- The frozen B2C code (intake, staff leads, traveller sign-in, B2C case fixtures) still inserts traveller rows as role
  `booking` in its tests. Conftest fixture `b2c_insert_regranted` gives INSERT back for one test and revokes it after;
  the modules that need it mark themselves with it (bk002, bk003, bk005, bk011 x2, bk012, bk024 intake, bk027, aa679;
  two tests of bk001 and one of bk024 schema).
- Old tests that re-run an old file whose grant bk-036 changes: `test_bk024_schema` (rerun ACL compare restates the
  bk-036 revoke; `test_grants` now expects no INSERT); `test_bk027_schema` replays the later files without bk-036
  (`LATER`), since the module regrants INSERT and the guard would refuse the replay.
- `CONTEXT.md`: a `bk-036` entry.

## Tradeoffs

- Regrant fixture vs rewriting 56 tests to insert as the owner: the B2C code is frozen and will be deleted with the
  tables, so the fixture keeps its tests honest with the least churn. The cost: those modules run with INSERT granted.
- No COMMENT on `booking.customers`: a table comment could collide with the DM-6.1 tag tooling; the CONTEXT entry and
  this note carry the "frozen" fact instead.
