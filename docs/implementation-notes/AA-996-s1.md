# AA-996 audit fix slice 1 — shared list and date pieces

Source: the S254 Figma visual audit (root repo `docs/audits/2026-10-28-S254-booking-figma-audit/README.md`, slice 1;
deviation items 4, 5, 8 (first half), 9, 10, the Destinations Actions header and the customers `PersonCell` note).
Frontend only. Session S254, agent Claude Code (lane, orchestrated). Main AA-996 notes: `AA-996.md`; this slice keeps
its own file so parallel AA-996 lanes do not conflict on one notes file.

## Decisions

- **Filter bar shape = Figma USER MANAGEMENT / PAYMENT & INVOICE, two fixed rows.** Row 1: search box, then the tools at
  the right (the table's Columns / CSV). Row 2: every filter with its label inline ("Status [All statuses]") and
  "Reset filters" at the right. The task text said "one row at 1440"; measured at 1440 px with the brand font, a single
  row with inline labels needs ~1190 px for Trip checks (4 selects) and ~1300 px for Trip plans (5 selects) against
  ~840 px left of the tools, so one row is not possible without hiding the labels. The Figma frames themselves use the
  two-row shape, and the audit's real complaints (a lone Sort / Status select on a second row, Columns / CSV floating on
  their own row) are gone: every list now has the same two rows, each one line at 1440 (checked by the harness).
- **How the bar joins the table toolbar without touching the kit.** The Booking `DataTable` wrapper got a `filters`
  prop. The wrapper renders the bar inside `.bk-dt-filters` with `display: contents`, and `app/globals.css` gives the
  bar's root `display: contents` there too, so the search box becomes a flex item of the kit toolbar (next to Columns /
  CSV) and the filter row (`order: 2`, `flex-basis: 100%`) wraps under them. `ui/DataTable.tsx` (byte copy of the CIS
  kit) is unchanged.
- **"Reset filters" is always drawn**, disabled while every filter is at its default: the bar never changes width when
  a filter is set (no layout shift), and the audit's "Reset filters missing" goes away on every list.
- **Labels inline, 12 px, muted**; every control 36 px high. `FilterField` is exported so page-specific controls
  (the cases Status multi-select) take the same shape.
- **Dates:** one `DateField` (text box: day-first input "28/10/2026", "28 Oct 2026" or ISO, shown as "28 Oct 2026"; a
  calendar button opens the browser's own picker through a hidden native input, so no home-made calendar) and one
  `TimeField` (24 h, "14:05"; accepts "1405", "2:05 pm"). Same value contract as the native inputs ("YYYY-MM-DD",
  "HH:MM", "" for empty), so every page swapped one line.
- **Calendar days are not instants.** `DateText` now shows a date-only value ("2026-10-09") with `formatDay` (UTC), so a
  due date or trip start no longer shows the day before for a viewer west of Greenwich. Timestamps are unchanged
  (kit `formatDate` / `formatDateTime`).
- **CSV:** `enableCsv` on Services, Hotels, Suppliers, Invoices, Payments, Proposals, Trip checks and the case
  Proposals tab. Display-only columns got an `accessorFn` with `enableSorting: false` (the kit CSV writes "" for a column
  without an accessor; sorting stays exactly as before). Countries (a card grid, no DataTable) gets `ExportCsvButton`
  (kit `toCsv` / `downloadCsv`) in the FilterBar `tools` slot.
- **Explicit CSV columns (`csv` prop on the wrapper)** when one table cell shows two facts: the invoices list keeps one
  CSV column per fact (invoice, trip case, customer, issued, next due, total, paid, left to pay, currency, status,
  overdue) although the table groups them.
- **Billing invoices at 1440** (deviation 5): codes, dates and amounts are `whitespace-nowrap`. With the widest real
  amounts (VND billions) the table needed 1201 px of 1078. Following Figma ("Trip case & customer"), the customer moved
  under the trip case code (the one truncating cell) and the amount paid under the total ("Total / paid"). Min-content
  is now 989 px.
- **Trip checks at 1440** (deviation 8, first half): the free-text cells truncate (Check 170, Customer 110, Owner 100 px,
  full text in the tooltip); min-content 1012 px fits 1400 and 1440 with ≥ 20 px to spare; Status is in view.
- **Customers:** the name column 220 → 260 px; Location 150 → 130 px keeps the 1400 px fit.
- **Text dates:** `formatDay` / `formatDate` / `formatMoney` in InvoiceView (sent date, next due, overdue / refunded /
  unverified amounts), the billing and supplier-bill KPI hints ("since 1 Oct 2026"), the bill drawer, invoice form,
  payment dialog and B2B desk aria label; notification titles and messages run through `localizeIsoDates` (ISO days and
  instants inside API-stored text).

- **Review fix: the box always shows what the page holds.** `DateField` passes a readable day up even outside
  `min` / `max` (the native input's contract) and marks it invalid, so the page's own checks (SendProposalModal
  `validUntil < min`, the API's 422) block the save; before, it kept the text and the old value, and Save / Send sent
  a date the screen did not show. Text that is not a day is marked while the field has focus (Enter keeps it to fix)
  and dropped on blur, so the box goes back to the stored value. `TimeField` follows the same rule. A value changed
  from outside (Reset filters, a removed schedule row) drops any pending text (render-time state adjustment, as in
  `ui/booking/DataTable.tsx`). Chosen over `onChange("")` on unreadable text: that would silently clear an optional
  date (e.g. a due date) on a typo.
- **Review fix: every Booking CSV goes through the wrapper's button.** The kit exporter writes every visible column,
  so the row menu became an empty "Actions" column, and it does not neutralise formulas; `ui/DataTable.tsx` is a CIS
  copy, so the wrapper now always draws its own CSV button (same look and place). Its file leaves out row tools
  (`__select`, the details button, `actions` / `open` / `menu`) and passes every value through `ui/booking/csvCell.ts`:
  a string starting with `=`, `+`, `-`, `@`, tab or CR gets a leading `'`, except plain numbers and amounts
  ("-50.00", "-50.00 USD") so refunds stay numeric. `ExportCsvButton` (Countries) uses the same guard. The audit log
  already had its own guard; left as is.
- **Review fix: Supplier bills exports CSV** (billing tab and the supplier page's Bills tab), one column per fact via
  the wrapper's `csv` prop (the Bill cell shows the code and the supplier's own number).
- **Review fix: date-only trip fields use `formatDay` everywhere** (cases list Dates / pax, case header, proposals
  list and search, send modal summary, proposal preview header and day headers), so the same trip start never reads
  one day on Trip checks and another on Cases west of Greenwich.

## Tradeoffs

- Two fixed rows cost ~46 px of height on lists with few filters (e.g. invoices: Status + Due) against a single row; in
  exchange every list has the same shape and nothing jumps rows as filters are added.
- DateField is a text box: the browser's own picker still opens from the button, but what is shown and typed is always
  en-GB. Month-first numbers ("10/11/2026") are read day-first on purpose (10 November).
- Invoices: the customer name is now a muted second line (Figma) and the paid amount a second line under the total;
  the compact drawer shows them in the "Total / paid" entry.

## Should know

- Hiding a column with the Columns menu no longer removes it from the CSV: every Booking CSV now exports every data
  column (already the case at compact density since the first review). All Booking lists filter in the page
  (`searchable={false}`), so the rows exported are the rows passed, as before.
- The send-modal case asked by the review (out-of-range Valid until disables Send) is not a Playwright case: the
  harness has no fixtures for the version items / settings the modal loads. The harness covers the same `DateField`
  rule on the cases "Created to" filter (out of range → passed up and marked), and `SendProposalModal`'s existing
  `invalid` check now receives the value.

- The layout harness is not in CI; evidence is a local run (`npm run build && npm run test:layout`).
- No `formatDate(...)` call on a date-only field is left in `app/` (review sweep); the only one left formats
  `issued_at`, a timestamp.
- `.bk-dt-filters > .bk-filterbar { display: contents }` relies on the bar being the direct child of the wrapper's
  `.bk-dt-filters` div (both Booking files); the kit toolbar is untouched.
