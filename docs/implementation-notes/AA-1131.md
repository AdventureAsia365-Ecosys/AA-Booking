# AA-1131 — Kit accessibility fixes, Booking side (S283 UI audit batch K1)

The kit core fixes (DataTable named page-size select and keyboard rows, Drawer name / focus / trap / return,
PageHeader text basis, PageFrame containing block) are made in the canonical AA-CIS-App `frontend/app/_kit/core` and
reach `frontend/ui/core` through `tools/kit/kit-sync.sh` (never edited here by hand). This note covers the Booking app
code that goes with them.

## Decisions

- **Sidebar footer pinned** (`ui/local/Sidebar.tsx`, the Booking shell, not kit core): the `<aside>` no longer
  scrolls; the nav does (`flex: 1 1 auto`, `min-height: 0`, a thin dark-surface scrollbar), and the footer (Settings,
  staff card, Collapse) is `flex: none`. The audit measured the aside at 928 px in a 900 px window with the Supply
  group open, so Collapse was cut at the bottom edge.
- **PageHeader rules**: the copy in `ui/local/shell.css` (AA-994 S4b) is removed; the kit core now ships the rules as
  its own stylesheet (`PAGE_HEADER_CSS`). Visible change: on a phone, a header with a description AND actions now
  stacks (actions on their own row under the text), as in CIS. S4b had left that rule out to keep pages unchanged;
  the audit's batch K1 asks for one behaviour in every app.

## Changed

- `ui/local/Sidebar.tsx`, `ui/local/shell.css`, `lib/shellA11y.test.mjs` (source checks), and the kit sync
  (`ui/core/*`, `kit.lock.json`) at the CIS commit that carries the kit fixes.

## Tradeoffs

- The nav scrolls inside the sidebar instead of the whole sidebar: on a short window the brand and the footer take
  their room first; the nav keeps the rest (about 600 px at 900 px high), enough for every group open.
