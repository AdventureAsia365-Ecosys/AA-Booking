# AA-1131 — Kit accessibility fixes, Booking side (S283 UI audit batch K1)

The kit core fixes (DataTable named page-size select and keyboard rows, Drawer name / focus / trap / return,
PageHeader text basis, PageFrame containing block) are made in the canonical AA-CIS-App `frontend/app/_kit/core` and
reach `frontend/ui/core` through `tools/kit/kit-sync.sh` (never edited here by hand). This note covers the Booking app
code that goes with them.

## Decisions

- **Sidebar footer pinned** (`ui/local/Sidebar.tsx`, the Booking shell, not kit core): the `<aside>` no longer
  scrolls; the nav does (`flex: 1 1 auto`, `min-height: 0`, a thin dark-surface scrollbar), and the footer (Settings,
  staff card, Collapse) is `flex: none`. The audit measured the aside at 928 px in a 900 px window with the Supply
  group open, so Collapse was cut at the bottom edge.
- **PageHeader rules**: the copy in `ui/local/shell.css` (AA-994 S4b) is removed; the kit core now ships the rules as
  its own stylesheet (`PAGE_HEADER_CSS`). Visible change: on a phone, a header with a description AND actions now
  stacks (actions on their own row under the text), as in CIS. S4b had left that rule out to keep pages unchanged;
  the audit's batch K1 asks for one behaviour in every app.

## Changed

- `ui/local/Sidebar.tsx`, `ui/local/shell.css`, `lib/shellA11y.test.mjs` (source checks).
- The kit sync (`ui/core/*`, `kit.lock.json`) is its own commit, the LAST on the branch (fix pass after review: the
  first push of this branch had no sync, so `lib/shellA11y.test.mjs` read a missing `ui/core/PageHeaderStyles.tsx` and
  the shell.css removal would have shipped before the kit's own PageHeader rules). Locally it is synced at the CIS
  branch commit, so the unit tests, tsc, lint and the visual run test the real kit; the lock's ref is that branch commit,
  which the Kit core provenance check rejects. Before the push the commit is redone at the merged CIS sha
  (`tools/kit/kit-sync.sh booking --dest-repo <worktree>`, default ref = CIS `origin/main`, then `git commit --amend`).
  If the Kit Sync bot's PR (`bot/kit-sync`) merges first, the amended commit carries the same bytes and lock, so the two
  merge cleanly in either order.
- Visual job (`e2e/visual/`): the role-name gate (`a11yNames.ts`, a copy of the CIS helper: a kit-rendered control
  with no accessible name fails on every page, any control on the kit gallery) and the kit keyboard check
  (`a11y-keyboard.spec.ts`: the gallery's table rows and drawer from the keyboard, at 1440 and 390). The fake session
  cookie moved to `e2e/visual/session.ts`, because proxy.ts sends the gallery to /login without one.

## Tradeoffs

- The nav scrolls inside the sidebar instead of the whole sidebar: on a short window the brand and the footer take
  their room first; the nav keeps the rest (about 600 px at 900 px high), enough for every group open.

## Should know

- Visual run on this branch (KIT_GALLERY=1 build, every page, both themes, 1440 and 390): 198 tests, all green with the
  role-name gate on (no unnamed kit control on any Booking page); the keyboard check passes at both sizes.

- Layout-mock run on this branch: 556 passed, 5 failed: pricing-rules ("Channel | Margin | Peak uplift" table 1144 px

  390). The 1440 cases fail the same way on `origin/main` without this change (re-run on a main build, identical
  numbers); the 1400 / 390 cases are the same two tests at other sizes. Pre-existing, not from this PR.
