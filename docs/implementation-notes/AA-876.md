# AA-876 — API edge hardening (AA-Booking part)

Scope here: gate `/booking/docs` + `/booking/openapi.json` on the public host, and pass the CIS login 429 through
the staff login BFF. The login throttle itself is in AA-CIS-App, the stage throttle in AA-CIS-Infra.

## Decisions

- **Gate, not remove.** Docs stay useful in local/CI (`ENVIRONMENT` in `INSECURE_ENVIRONMENTS` = `test`, `local`:
  open). Everywhere else they need a staff Bearer with `staff.admin`. Mirrors the CIS AA-577 approach (gated by a
  credential on the real deployment) with Booking's own credential (staff JWT) instead of an admin secret.
- **One answer for every refusal: 403 `docs_forbidden`.** No token, a bad token, JWKS unavailable (503), no Booking
  role, inactive or not an admin all look the same, and there is no `WWW-Authenticate` hint. Done-when asks for 403
  on the public host.
- Routes are registered by hand in `app/routers/docs.py` with `include_in_schema=False`; `create_app` sets
  `docs_url=None, openapi_url=None` (ReDoc was already off). `app.openapi()` still builds the schema.
- BFF: a CIS 429 becomes `fail("Too many sign-in attempts. Try again in a few minutes.", 429)` with `Retry-After`
  forwarded when CIS sent one (the API Gateway 429 has none). Checked before the `!res.ok` 502 branch.
  `LoginForm.tsx` already shows `message`.

## Changed

- `backend/app/main.py`, new `backend/app/routers/docs.py`.
- `backend/tests/unit/test_docs_gate.py` (new); `test_health.py::test_only_booking_prefix_is_served` now expects
  403 on `/booking/openapi.json`, because its `SETTINGS` are `ENVIRONMENT=dev` (the gate's own tests cover 200).
- `frontend/app/api/auth/login/route.ts`: 429 branch; `fail()` takes optional headers.
- `CONTEXT.md`: layout line + auth section bullets.

## Tradeoffs

- The Swagger page's own schema fetch carries no Bearer, so on Dev the docs are usable only with `curl` and a token.
  Acceptable: nobody needs Booking docs on Dev in a browser; locally they are open.
- `current_staff` may provision or sync the caller's `booking.staff_users` row (a DB write) — the same write any
  staff request makes, so no new behaviour.

## Should know

- Run tests with `ENVIRONMENT=test` (as CI does); the settings default is `dev`.
- No migration, no env var, no secret.
- Live check after deploy: `curl -s -o /dev/null -w "%{http_code}" https://api-booking.lumiguides.it.com/booking/openapi.json`
  → 403, same for `/booking/docs`; `/booking/health` still 200.
