# AA-1013 — Proposal read-back after CIS rewrites (S262 lane w4k-booking-1013)

The S261 live check for AA-990 (root `docs/audits/2026-10-31-S261-evidence/AA-990/`, findings F1–F3) found three
Booking gaps after CIS rewrote every tour (S1 v2, 25/10/2026):

- **F1:** proposal items keep the day titles copied when the version was made, still tagged "From CIS". TC-000008 V2
  matched 1 of 7 of today's CIS day titles, and nothing told staff.
- **F2:** the customer-style preview scrolled sideways by 257 px at 390.
- **F3:** a B2B proposal made by the CRM AA confirm showed "trip_plan tp:<id> · line <id>" instead of the tour name.

## Decisions

- **Read live, never copy (root ADR 0002).** No migration. Every items response (`GET …/versions/{n}/items`, the
  create and save responses) gives each item `cis`. It is null when the item has no catalog tour, or when the
  catalog cannot be read. Otherwise it holds:
  - `source_id`, `tour_title` and `tour_updated_at` (`v_tour.updated_at`);
  - `day_number` and `title`: the CIS day the item stands for, and that day's title today;
  - `changed`: the stored title differs from it, ignoring whitespace (the S261 parity method).
- **Which CIS day an item stands for.** Only a tour whose items on the version look like a day-by-day copy (the
  shape `items_from_days` writes) is compared day by day. Its first item is CIS day 1, and the rest count on from it
  (`day_from - first + 1`), so a tour placed later in a trip still lines up. A tour's items are a day copy when
  (`cis_readback.day_copies` + `day_numbers`, fix pass after review):
  - every one of them is one day long. A multi-day item (a TripPlanner leg, a B2B trip plan line, a tour without CIS
    days) is never compared;
  - none is a B2B confirm item: notes starting "Agency line " (this slice) or a cost line noted "B2B quote " (every
    B2B confirm since bk-020, so older cases too). A B2B line names what was sold, even when the plan spans one day
    (`coalesce(max(day_no), 1)` = 1 writes a one-day item) or a tour sits on two one-day lines;
  - none is titled with the CIS tour title or the TripPlanner fallback "AA tour <key>" (`sql.leg_fallback_title`).
    An item that names the tour is not out of date;
  - the tour has two or more such items, or one item and CIS has exactly one day for it. A lone one-day item of a
    multi-day tour (a one-day TripPlanner leg) is not a day copy.
  - Items that are not compared still carry `tour_title`. The UI shows it under every item that is not a day copy
    (`cis.day_number` null), one-day B2B lines and legs included, so older B2B items with technical titles name their
    tour too.
- **Refresh is a staff action, client side.** "Refresh from CIS" in the builder copies today's titles into the draft.
  The page shows "Unsaved changes", and nothing is written until staff press Save (the existing `PUT …/items`, items
  keep their ids).
  - No new endpoint, no new permission and no new audit action. The save is audited as
    `trip_case_version.items_replaced`.
  - A sent or approved version is locked (bk-005 / bk-003 triggers). Its notice says to make a new version and
    refresh that one.
- **Stale is judged on the draft title in the browser** (`ui/booking/cisReadback.ts` `cisNewTitle`), not on the
  server's `changed`. A refreshed or hand-typed title clears the flag before the save. The server's `changed` is for
  other readers of the API.
- **B2B confirm titles.** Each item title says what was sold:
  - a trip plan line: the CIS tour title (`catalog.v_tour` by the plan's `source_id`);
  - a room line: "hotel · room type";
  - a service line: the service title.
  - When the name cannot be read, the title falls back to the kind ("Trip plan <source_id>", "Hotel room",
    "Transfer"). A catalog error never fails the confirm: the read runs in a savepoint, and `served.require_served`
    has already checked the tour.
  - The version title is the first trip plan line's tour, else the first line's title.
  - The agency proposal ref and version move to the version notes ("Agency proposal P-1 v1"). Each line ref moves to
    its item's notes ("Agency line L1"). The case keeps `source_id` = the proposal ref.
- **390 px.** The preview grid had no column template under `lg`. Its implicit `auto` track grew to the min-content of
  the `truncate` (nowrap) day titles, and the whole column (footer text included) spilled out.
  - The fix: `grid-cols-[minmax(0,1fr)]` below `lg`, plus `min-w-0` on both columns. Day titles now wrap instead of
    truncating, since a customer-style page should show the whole title.
  - The builder got the same track (it was not flagged, but has the same structure).
  - Checked in plain Chromium on a stand-alone copy of the structure: 463 px of overflow before, 0 after.

## Tradeoffs

- **Review fix pass (two major findings, same root cause).** The first cut compared every tour whose items were all
  one day long, so a one-day B2B plan line (titled with the tour) and a one-day TripPlanner leg (titled from the
  snapshot) were compared with CIS day 1 and flagged "CIS has newer text" though CIS rewrote nothing. Fixed with the
  checks above. Rejected: skipping versions by `channel = 'b2b'`. A staff "Use for trip case" on a plan whose default
  channel is B2B writes real day copies on a B2B-channel version, so the item markers are used instead.
- **Day trips titled with the tour.** A one-day CIS tour whose day 1 title equals the tour title, copied day by day,
  is no longer compared once CIS rewrites that day title. Accepted: the item still names the tour correctly, and this
  is what keeps a B2B or hand-titled item from being flagged.
- **A one-day TripPlanner leg of a one-day CIS tour** whose snapshot day name differs from CIS day 1 is compared. The
  TripPlanner snapshot takes that name from CIS, so a difference is a real CIS change.

- **Offset mapping and deleted days.** If staff deleted the day-1 item of a day-by-day copy, the offset moves by one
  and every remaining item would be flagged against the wrong CIS day.
  - Mapping by `day_from` directly would instead mis-map a tour placed later in the trip.
  - The flag only offers a refresh that staff review. It is never applied by itself, so the rarer error was accepted.
- **A title refresh clears the version's price.** The existing rule "a price belongs to one item list" (any item
  change clears `total_price`) was kept. Staff apply the price again before sending. Exempting title-only changes
  would be a pricing-rule change outside this issue.
- **Day bodies are not read back.** The preview still shows stored titles and notes. Showing live CIS bodies next to
  stored titles would mix two sources on a customer-style page. The trip plan page already shows the live days.
- **Older B2B cases (TC-000025 / TC-000026) keep their technical titles in the database.** Their versions are approved
  and locked by trigger. The read-back's "Tour: …" line names the tour on screen; no data fix was made.

## Should know

- The perf guard holds:
  - `DAYS_SQL` is keyed `tour_id = ANY($1::uuid[])` and never names `source_id`.
  - `TOURS_SQL` reads `v_tour` (not parse-backed) by key, like `app.inquiry.leg_keys`.
  - Both views are read once per items response, never per item.
  - The integration run's EXPLAIN check passed.
- Every catalog read runs in a savepoint and catches `asyncpg.PostgresError` / `TimeoutError`. A save or create inside
  a transaction is never aborted by a catalog problem.
- Live check (Dev): TC-000008 V2 is a draft made 16/10, before the rewrite. It should show the notice, with 6 of 7
  "CIS now" lines.
  - The agent E2E Booking identity is read-only (`e2e_read_only`). Pressing Refresh works in the browser, but Save
    needs a writer session.
  - A new B2B confirm from the CRM shows the tour name. TC-000025 / TC-000026 show "Tour: …" under the old titles.
