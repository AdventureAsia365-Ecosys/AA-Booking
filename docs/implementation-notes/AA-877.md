# AA-877: DM-6.1 tags on the Booking columns (bk-018)

## Decisions

- **COMMENT ON COLUMN only, one file (bk-018).** Static statements, a `current_user = 'bk_owner'` guard, the
  `shared.schema_versions` row. No grant, no DDL, no EXECUTE, no role switch. `REQUIRED_SCHEMA_VERSIONS` is unchanged
  (bk-017 precedent: a migration-only PR, `/ready` is not affected).
- **Columns already tagged are not re-issued**: bk-008 (`suppliers.contact_name` / `contact_email` / `contact_phone`,
  `suppliers.internal_notes`, `supplier_contracts.payment_terms` / `cancellation_policy` / `notes`), bk-009
  (`trip_plans.default_channel`, `price_hint_*`, `commercial_notes`), bk-010 (`*.internal_notes` of hotels, room
  types, services; `supplier_rates.net_amount` / `notes`), bk-012 (`inbox_events.payload`).
- **Old text kept verbatim after the tag** for the columns that had an untagged comment: `trip_cases.inquiry_snapshot`
  (bk-002), `trip_cases.pax_adults` (bk-005), `staff_users.cis_user_id` / `cognito_iss` / `cognito_sub` (bk-016),
  `pricing_rules.target_margin` / `floor_margin` / `peak_uplift_pts` / `card_fee_pct` (bk-004). Texts are taken from
  the migrations; the review gate compares them with the live catalog (AA-CIS-Infra baseline dump after its AA-877 PR).
- **Classes decided from the code**, not left conditional:
  - `notifications.data` = `pii:contact`: proposal.sent rows store `data.to` = the customer e-mail
    (`app/trip_cases/versions.py`).
  - `notifications.title` = `pii:free_text`: on customer rows it is the subject staff typed.
  - `notifications.message` = `pii:free_text`, also `pii:name` (inquiry rows start with the contact name).
  - `audit_logs.summary` / `entity_label` = `pii:free_text`, also `pii:name` ("Created manual lead {name}";
    staff name on staff rows, `app/auth/admin.py`).
  - `audit_logs.before` / `after` = `pii:free_text`, also `pii:name`, `pii:contact` (row snapshots; redacted, not
    deleted, DM-6.7).
  - `trip_case_versions.title` = `pii:free_text` (staff-written proposal title sent to the customer), not allowlisted.
  - `staff_users.cis_user_id` = `pii:online_id` ('cog:' || Cognito sub on WORKFORCE rows).
  - `media_files.s3_key` = `pii:profile`, with the note that nothing uploads yet and the link is
    `customers.profile_media_id`.
  - `customer_otps.otp_hash`, `customer_sessions.refresh_token_hash` = `conf:credential`.
- **Block C (conf:commercial)** is kept and marked separately: `pricing_rules` margins (+ bk-004 text) and `note`,
  `policy_approvals.note`, `version_item_costs.net_amount` / `supplier_note`. Cutting it means allowlisting the three
  `note` columns instead.
- **Left untagged on purpose**: ids, FKs, `*_by` / `*_ref` staff keys, `customers.code` / `external_ref`, consent flags,
  timestamps, `staff_users.last_seen_at` / `preferences`, `notification_reads.cis_user_id`, supplier and hotel business
  names and addresses, `booking.job` payload / result / error (ids only), `trip_case_legs`, `trip_case_countries`.

## Tradeoffs

- The candidate token list and allowlist exist here and in AA-CIS-Infra `db/gen_schema_reference.py`. The Infra
  generator is the authority for the reference; this test asserts an explicit map plus the token rule so a new
  untagged column fails in Booking CI before it reaches Dev. The two lists can drift; drift shows up as an untagged
  candidate in the reference.
- Name-based checks cannot see PII inside jsonb or free text; the explicit map from the code reading is the evidence.
