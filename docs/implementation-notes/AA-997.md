# AA-997 — Booking staff readers of hidden and merged CIS places (S260 lane L12)

Follow-up of the CIS AA-997 hide policy (CIS `docs/implementation-notes/AA-997.md` Part 4, "Readers that do NOT drop
suspect rows"). CIS hides about 2,000 flagged destinations from customer maps (`shared.destinations.geo_status =
'suspect'`) and merges duplicates (`duplicate_of`). `catalog.v_destination` still lists both kinds of row, so the
Booking staff screens showed them as ordinary places.

## Decisions

- **Staff keep seeing every place, with its coordinates.** Booking is a back office: the job here is to let staff
  review a hidden place, not to hide it again. Each destination row (list, detail, a country's places, the picker)
  now carries `hidden_from_customers` (bool), `hidden_reason` (`location_unconfirmed` | `merged` | null) and
  `merged_into` (the keeper id of a merged place). A merged row that is also suspect reads `merged` (staff look at
  the keeper).
- **Sources: existing contract views only.** `catalog.v_destination.geo_status` (CIS 228) and
  `catalog.v_destination_redirect` (CIS 257, SELECT to `booking`). No CIS change, no Booking migration. The CIS
  `review_reason` (why a point is suspect: `llm_point`, `off_route`, …) is not in any view, so Booking can only say
  "location not confirmed"; a finer reason needs a CIS contract change (append `review_reason` to
  `catalog.v_destination`, CIS-owned) — not done.
- **List filter `visibility=shown|hidden`** (`GET /booking/catalog/geo/destinations`), summary count `hidden`.
- **Supplier place picker** (`GET /booking/catalog/destinations`): never lists a merged place, so a new supplier is
  attached to the keeper. A write naming a merged id (create, or an edit that changes the place / country) is 422
  `merged_destination` with `merged_into`. A supplier that already holds a merged id keeps it and its name still
  resolves (`destinations_by_id` is unchanged apart from the new keys). A place with an unconfirmed point stays
  pickable: the place exists, only its pin is in review; the picker shows no coordinates.
- **UI:** a warning pill "Hidden from customers" under the name in the Destinations table (tooltip = reason), a
  "Customer maps" fact in the destination drawer (Shown / Hidden + reason), and a "Customer maps" filter. Coordinates
  stay visible. Kit components only (`Pill`, `FilterBar`, `Fact`).

## Changed

- `backend/app/catalog/geo.py`: `HIDDEN_SQL`, `HIDDEN_REASON_SQL`, `VISIBILITIES`, `_visibility`; `DEST_COLUMNS` /
  `DEST_FROM` join `catalog.v_destination_redirect rd`; `list_destinations(visibility=)`; summary `hidden`.
- `backend/app/catalog/destinations.py`: `DESTINATION_SQL` joins the redirect view and returns the three fields;
  `search_destinations` drops merged rows; `require_destination` refuses a merged id.
- `backend/app/routers/catalog.py`: `visibility` query parameter. `docs/api/openapi.json` regenerated (additive).
- Frontend: `lib/api/geo.ts` (`HiddenReason`, `CustomerVisibility`, item / summary / query fields),
  `lib/api/suppliers.ts` (`CatalogPlace` optional fields), `GeoDrawers.tsx` (`CustomerVisibilityBadge`,
  `HIDDEN_REASON_LABEL`, drawer fact), `DestinationsView.tsx` (pill, filter), layout fixture.
- Test stub `tests/integration/stub_catalog.sql`: `catalog.stub_destination_state` (geo_status / duplicate_of per
  fixed place, empty by default so every existing count is unchanged), `v_destination.geo_status`,
  `catalog.v_destination_redirect`, grant to `booking`.

## Tradeoffs

- The country counts (`COUNTRY_CTE` `destinations`) still count hidden and merged places: they describe the CIS
  catalog staff manage, same as the list. Changing them would make the country page and the list disagree.
- 422 on a merged id instead of silently storing the keeper: the staff member sees which place to pick; a silent
  swap would change the supplier's place without an audit entry naming it.
