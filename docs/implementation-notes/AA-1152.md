# AA-1152 — optional activities per day for customers and agencies (Booking part)

Slice L9 of the root `docs/audits/2026-11-19-S285-session/advisory-r2-plan.md` (PR-29 T6 and B2 option C). The
TripPlanner day cards and the CRM drawer live in their own repos; Booking serves the agency read of the add-ons.

## Decisions

- **One read for both CRM uses**: `GET /booking/b2b/v1/add-ons` (contract `booking.b2b.v1` 1.11) serves the
  "AA add-on" drawer (one day: `date`, the party as `pax`) and the agency's own "from" prices (no `date`, no place:
  every published offer once, with its first sellable day). The CRM never reads `booking.v_place_addons` (root ADR
  0008a: `crm_app` reads nothing outside `crm`).
- **Prices per traveller, from the quote engine**: the row is priced like an `sv:` quote line for `pax` adults on its
  day (`components.price_lines` + `quotes.price_line`, the agency's discount off), then shared over the party and
  rounded up like a line. Nothing is stored: the quote fixes the price.
- **RRP for add-ons** (advisory B2 step 1: "CRM only has an RRP fallback for tours"): the same sell price before the
  agency discount, plus the B2B rule's `rrp_markup_pct`, up to the pricing policy's `rounding_increment_by_currency`
  (like `engine.rrp_price` for tours). A currency the policy does not round (VND) is rounded like a quote line.
- **Unpriced rows stay listed** with null prices (a cost currency without an FX rate, a rate the batch could not
  read): the quote decides, the drawer says "priced when quoted".
- Own router file (`app/routers/b2b_addons.py`) so `app/routers/b2b.py` stays within the code health limits; model
  names `AgencyAddon*` because the staff router already has `AddonPlace`.

## Changed

- Nothing in the sale rules or the view: the `min_pax`, weekday and cut-off checks stay in `POST /quotes`.

## Tradeoffs

- A row is priced for adults only (`pax` adults): the drawer quotes the real party (children by age) with
  `POST /quotes`. A per-traveller price of a group unit depends on `pax`, so the CRM asks with the party it prices.
- At most 200 offers per answer (`truncated`), priced with one batched rate query (one ask per offer).
